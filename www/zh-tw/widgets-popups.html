彈出視窗與對話框

gohud 的所有彈出視窗 —— 該選哪一個、如何開啟與關閉、對返回鍵和輸入做了什麼，以及在每種外觀下的樣子。 ← 控制項

控制項 所有控制項 彈出視窗與對話框 浮動視窗 告訴玩家某件事 HUD 等待、告知、計數 表單與清單 遊戲真的會用到的形狀 蓋在畫面上 GoStyle — 東西統一在一個地方產生

挑對彈出視窗

彈出視窗會打斷玩家。挑選之前，先回答一個問題：玩家必須先回答，遊戲才能繼續嗎？ 是，就擋住；不是，就絕對不要擋 — 為了玩家根本沒問過的消息把遊戲停下來的卡片，是讓玩家關掉你的遊戲最快的方法。

  1. 有答案的問題 — 購買、刪除、離開、覆寫 → GoDialogs.confirm()。只需要知道的事 → alert()。從幾個選項中挑一個 → choose()。
  2. 自成一頁的畫面 — 設定、角色面板、商店裡的一件物品 → 畫面正中央的 GoSurface。
  3. 長清單或管理頁面 — 背包、郵件、好友 → 手機上從底部升起的 GoSheet，寬螢幕上從側邊滑入的 GoDrawer。
  4. 關於剛按下那個東西的資訊 — 物品屬性、可以做的動作 → 在它旁邊彈出的 GoPopover 或 GoContextMenu。
  5. 遊戲可以照常進行的消息 — 已存檔、已丟棄、收到邀請 → GoSnackbar、GoNotice 或 GoPromptCard。它們從不佔據畫面。
  6. 教玩家怎麼操作 → GoCoachMark。開發時用的作弊 → GoConsole。

彈出視窗的構造

gohud 裡幾乎每一個會擋住遊戲的彈出視窗 — 對話方塊、底部面板、錨定卡片、組合方塊的清單，以及你自己的 視窗 — 都是同一個節點：GoSurface。把它的各個部分認識一遍，就全部都認識了。

部分是什麼用什麼控制
圖層彈出視窗所在的 CanvasLayer。它的編號決定它能蓋住什麼。GoSurface 由你提供；其他彈出視窗已內建（見表格）
遮罩蓋在後面一切之上的那層布幕。沒點中卡片的點按由它接住。scrim_transparent、dismiss_on_scrim、佈景主題的 scrim 顏色
卡片視窗本身 — 佈景主題的面板表面，依外觀不同而是圓角、切角、鍛造或果凍。card、alpha
頁首可選的返回按鈕、標題（最多兩行，超過就顯示「…」）、關閉按鈕。set_title() · set_title_key() · set_back() · close_enabled · show_header
工具列頁首下方固定的一列 — 搜尋欄、篩選用的方塊標籤。沒用到時一直隱藏。toolbar

頁尾固定在底部的按鈕。沒用到時一直隱藏。footer
該固定的東西就放進固定的列。把搜尋欄、錯誤訊息或「儲存」按鈕放進本文，清單一長就會被捲走 — 玩家輸錯了名稱，錯誤訊息卻在可見範圍之外，看起來就像什麼事都沒發生。 請用 toolbar、狀態列與 footer；本文捲動時它們會留在原地。

可以 await 的對話方塊

GoDialogs 負責發問與等待。一個節點，三種問法 — 答案就在同一行回來， 所以程式碼的順序就是玩家經歷的順序。

var dialogs := GoDialogs.new()
add_child(dialogs)

if await dialogs.confirm("Buy the starter pack?", "300 gems for a sword, a shield and 10 potions.",
        "Buy", "Not now"):
    buy_starter_pack()

三種問法

confirm(title, body, ok_text := "", cancel_text := "", extra := "",
        args := {}, destructive := false) -> bool
alert(title, body, ok_text := "", extra := "", args := {})      # 用 await 等它結束
choose(title, options: Array, cancel_text := "", translate := false) -> int
confirm_key(…) · alert_key(…)                                 # 翻譯鍵
呼叫回傳用途
confirm()true 或 false是或否 — 購買、刪除、離開、覆寫。
alert()沒有 — 用 await 等它結束玩家一定要看到的事：獎勵、連線中斷。
choose()選項的索引，或 -1從幾個當中挑一個。選項可以是 String，也可以是 {text, icon, danger, subtitle}。
confirm_key() · alert_key()同上同樣的呼叫，只是改用翻譯鍵 — 對話方塊開著時切換語言，文字也會跟著變。

按鈕標籤留空時，會退回套件自己的用字（GoConfig.text_keys 裡的 confirm、cancel）。 extra 會另起一行接在本文後面。args 會填入標題與本文裡的 {placeholders}：confirm("Buy {item}?", "It costs {price} gold.", "Buy", "", "", {"item": name, "price": 300})。

每一種離開方式都有答案

玩家……confirmalertchoose
按下確定／某個選項true返回該選項的索引
按下取消false—-1
按下 ×、Esc 或 Android 返回鍵false返回-1

所以 await 之後的程式碼一定會執行 — 不會有哪個回答一直懸著，就算對話方塊底下的場景已經換掉也一樣。

破壞性動作

無法復原的動作請傳入 destructive = true。確定按鈕會變成實心的 Tone.DANGER_SOLID 按鈕 — 在每一種外觀下都是紅底白字；而著色的危險標籤在淺色佈景主題上 必須一路變深到接近黑色才讀得清楚。因為視窗會被重複使用，色調在每次呼叫時都會重設。

if await dialogs.confirm("Delete this save?", "Slot 2 — Aria, level 12. This cannot be undone.",
        "Delete", "Keep it", "", {}, true):
    delete_save(2)
確定按鈕握有鍵盤焦點。每個確認對話方塊打開時，焦點都在確定按鈕上，所以按 Enter 或空白鍵就會確認 — 破壞性的也一樣。按鈕的用詞要讓安全的選擇一眼就看得出來（「保留」）；一失手就會讓玩家損失真正進度的不可逆動作， 請放到第二個步驟之後。

按鈕排列

action_layout作用
VERTICAL（預設）按鈕上下堆疊、佔滿整個寬度。對每種語言都安全 — 德文或俄文的長標籤永遠不會被擠壓。
HORIZONTAL排成一列，各佔一半寬度。
AUTO只有兩個標籤都能在卡片一半寬度內單行放下時才排成一列，否則上下堆疊。切換語言或改變大小時會重新判斷。

action_gap 是按鈕之間的間距，body_gap 是按鈕上方的間距 — 把後者調得比按鈕間距更寬， 問題與選項才會讀起來像兩個部分。只想改某一個對話方塊時，在開啟之前呼叫 set_next_action_layout()。提示對話方塊唯一的那顆按鈕永遠佔滿整個寬度。

一次只開一個

已經開著一個時再呼叫 confirm()，會立刻回傳 false — 對話方塊絕不會意外疊在對話方塊上。 打開 queue_when_busy，它就會改成排隊等候；alert() 一律排隊等候。 queue_limit（8）限制隊伍的長度，滿了的時候最早的請求會得到 false。 pending() 計算正在等候的請求數，clear_pending() 讓它們全部得到 false。 choose() 從不排隊：已經有對話方塊開著時，它回傳 -1。

手機與桌機

在 Android 與 iOS 上，choose() 會以底部面板的形式從下方升起 — 那裡正是拇指所在的位置；在桌機上則是 畫面正中央的一張卡片。確認對話方塊的寬度上限是 max_width（420dp），並且置中顯示。layer_index、 max_width 與其他匯出屬性請在 add_child 之前設定；它們在節點進入場景樹時才會套用。

var picked := await dialogs.choose("Sort the bag by", [
    {"text": "Newest first", "icon": GoIconSet.CLOCK},
    {"text": "Rarity", "icon": GoIconSet.STAR},
    {"text": "Drop everything", "icon": GoIconSet.TRASH, "danger": true}])
if picked >= 0:
    sort_bag(picked)

GoSurface — 你自己的視窗

當彈出視窗不只是一個問題 — 設定、角色面板、要購買的物品 — 就在 GoSurface 上打造。安全區域、鍵盤、固定列、捲動、返回鍵、焦點與改變大小都已經處理好了。

var layer := CanvasLayer.new()
layer.layer = 50
add_child(layer)

var window := GoSurface.new()
window.set_title("Settings")
window.close_requested.connect(layer.queue_free)
window.body.add_child(GoStyle.toggle("Music", false))
window.body.add_child(GoStyle.slider(0.0, 1.0, 0.05))
var row := GoStyle.row()
row.add_child(GoStyle.button("Cancel", window.request_close))
row.add_child(GoStyle.button("Save", save_and_close, GoStyle.Tone.PRIMARY))
window.footer.add_child(row)
window.footer.visible = true
layer.add_child(window)
它從不自己關閉。×、Esc、返回鍵與點按遮罩都只會發出 close_requested。要隱藏還是釋放 視窗，是持有它的那個畫面的責任 — 只有它知道「關閉」代表儲存、捨棄，還是先問一聲。

三種擺放方式

ANCHOR 需要設定 anchor_control。右側放得下 anchor_min_width 時，卡片會放在它的右邊； 否則放在比較寬的那一側；再不行就放在畫面內；上方空間比較大時則往上展開。錨點移動時，它每一格都會跟上。 anchor_width（320）與 anchor_max_height（520）決定它的大小。

底部面板與抽屜

需要空間的清單，在直拿的手機上從底部升起 — 那裡正是拇指所在的位置；在平板或桌機上則從 側邊滑入，因為在那裡底部面板會把遊戲蓋住。

GoSheet — 從底部升起的頁面

var sheet := GoSheet.new()
add_child(sheet)

func show_bag(items: Array) -> void:
    sheet.open("Bag")
    var search := GoStyle.line_edit("Search the bag…")
    search.text_changed.connect(filter_bag)
    sheet.toolbar().add_child(search)
    sheet.toolbar().visible = true
    for item in items:
        sheet.body.add_child(GoStyle.list_button(GoIconSet.BOX, item.name, show_item.bind(item),
            Color.TRANSPARENT, item.description, false, GoIconSet.CHEVRON_RIGHT))
    sheet.add_footer(GoStyle.button("Close", sheet.close, GoStyle.Tone.PRIMARY))
  • 它是一個 CanvasLayer（圖層 10），裡面裝著一個 BOTTOM、可以改變大小的 GoSurface — 所以它待在 HUD 之上，玩家還能把它拉高。
  • open(title) 會開始一個全新的頁面：清空本文、工具列與返回按鈕，並釋放 add_footer() 加進來的東西。再呼叫一次，就能在同一個底部面板裡顯示另一頁；set_back() 會顯示一顆 用來回到首頁的返回按鈕。open_key() 收的是翻譯鍵。
  • close() 只是把它隱藏 — 並不釋放，所以下一次 open() 會立刻完成。closed 與 page_changed 會告訴你什麼時候發生。
  • height_ratio（0.6）是它打開時的高度；max_height_ratio 提高上限；dismissable （true）讓點按遮罩時關閉它。
Esc 與返回鍵會關閉整個底部面板，即使目前是用 set_back() 進入的子頁面 — 只有畫面上的返回按鈕 才會退回上一頁。如果返回鍵應該退回一頁，請自己在 sheet.surface 上處理 close_requested。

GoDrawer — 從側邊滑入

var drawer := GoDrawer.new()
drawer.side = GoDrawer.Side.LEFT
drawer.follow_text_direction = true      # 起始那一側：一般在左邊，阿拉伯文底下在右邊
add_child(drawer)
drawer.body.add_child(GoNavBar.drawer_list([{"icon": GoIconSet.HOME, "text": "Town"},
    {"icon": GoIconSet.MAP, "text": "World map"}], 0, go_to))
drawer.open("Menu")
  • 圖層 80。寬度是畫面的 42%（width_ratio），介於 min_width（320dp）與 max_width （420dp）之間 — 在手機上它會蓋住大半個畫面，所以在那裡底部面板是比較好的選擇。
  • 面板一路延伸到畫面邊緣；只有裡面的內容會從安全區域往內縮，所以圓角絕不會切掉第一列。
  • 就算在阿拉伯文底下，LEFT 也是指畫面左側。你要的是「起始那一側」時，請打開 follow_text_direction；effective_side() 會告訴你它最後在哪一側。
  • open(title) 會保留本文 — 填一次就夠了。set_title("") 會隱藏頁首。 motion_seconds（0.2）控制滑入；reduce_motion 讓它立即出現。
Android 返回鍵會關閉抽屜，Esc 不會。抽屜只監聽系統的返回鍵。在桌機上，請在你自己的按鍵綁定裡呼叫 drawer.close() — 另外注意，GoSurface.is_any_open() 不會把抽屜算進去； 要問 drawer.is_open()。

控制項旁邊的卡片與選單

玩家剛按下的東西，答案應該出現在手指旁邊，而不是畫面正中央。

GoPopover — 釘在被按下之物旁的卡片

slot.pressed.connect(func() -> void:
    var card := GoStyle.item_card({"icon": GoIconSet.POTION, "title": "Health potion",
        "subtitle": "Heals 50 HP · 12 left"}, false)
    GoPopover.open(slot, card, {"width": 280}))

一個 ANCHOR 擺放的視窗，圖層、錨點與善後都已經接好 — 就是每個遊戲都要一再重寫的那十行。 一次只開一張：打開第二張會關掉第一張，因為卡片疊起來會把畫面埋掉，誰也分不出哪張屬於哪一格。 遮罩是透明的 — 為了比較裝備而打開的卡片，不可以把裝備變暗 — 但它仍然會接住外面的第一次點按： 卡片隨之關閉，這次點按也不會再往下傳。

title""附 × 的頁首。空字串代表沒有頁首。

GoPopover.close() 與 GoPopover.is_open() 是靜態方法。open() 回傳這個視窗 — 錨點不在場景樹裡時則回傳 null，所以在 await shown.close_requested 之前請先檢查。

它不是滑鼠停留提示。觸控沒有停留這回事；只有滑鼠才叫得出來的東西，對你一半的玩家來說是看不見的。 而在 dismissable = false 又沒有標題時，畫面上沒有任何東西能關閉它 — 只有 Esc、返回鍵或你自己的呼叫。

post() 的鍵作用
text · title · args · translate訊息、可選的粗體行、{placeholders}、翻譯鍵。
tone · icon強調色（GoTheme.SUCCESS、WARNING……）與圖示。
actions · closable按鈕 — String 或 {text, action} — 以及一個 ×。
seconds停留多久。負數：使用佈景主題的 notice_duration_ms。0：直到被關掉 — 這時一定要給它一顆按鈕。

post() 回傳被按下的按鈕的索引；逾時或被關掉時回傳 -1。訊息會排隊 （queue_limit 為 4，最早的一則以 -1 被丟掉），正在顯示時再送一次相同的文字，只會重設它的計時。 它待在底部（或頂端，見 placement），在安全區域與鍵盤之上，圖層 90 — 蓋在抽屜上也讀得到。 開啟 tap_to_dismiss（預設開啟）時，點按沒有按鈕的卡片會關閉它；點按卡片以外的地方則一律 傳給遊戲。show_text() 與 show_key() 是一行的簡寫。

絕對不要在訊息條裡發問。它會自己消失；重要的選擇應該放進對話方塊。

圖層、返回鍵與輸入

有東西開著時玩家碰得到什麼，由三條規則決定：誰在最上面、誰握有返回鍵、 誰接住點按。

這個順序是刻意安排的：訊息條回報的是剛剛發生的事，所以蓋在抽屜上也要讀得到；錨定卡片屬於剛按下的東西， 所以待在它上面；對話方塊提出問題，把兩者都蓋住；主控台蓋住一切，因為它是其他東西都出問題時你要打開的那一個。

誰握有返回鍵

  • 只有最上層的視窗會回應。在開著的視窗當中，圖層最高的那一個（同一層時取場景樹中最晚加入的） 接收 Esc、遊戲手把的取消鍵（ui_cancel）、Android 返回鍵與遮罩點按。疊起來的視窗一次關一個， 絕不會一起關掉。
  • Android 返回鍵會延後一格才處理，所以按一下絕不會關掉兩個視窗。
  • 只要有任何握有返回鍵的東西開著，Android 返回鍵就不會結束應用程式（GoBackPolicy 計算持有者， 並在最後一個關閉後還原 quit_on_go_back）。你自己的彈出視窗如果接管了返回鍵，應該呼叫 GoBackPolicy.acquire() 與 release() — 在 _exit_tree 裡也要呼叫。
  • 有視窗開著時，抽屜、導覽與表單都會讓路 — 返回鍵先交給視窗。
  • GoConfig.close_on_back（預設開啟）是視窗這一項的開關。

誰接住點按

  • 視窗蓋住整個畫面並擋下輸入 — 透明遮罩也一樣。它開著時，較低圖層上的任何東西都按不到； 它上面的圖層（例如訊息條）仍然按得到。
  • 滑鼠滾輪與雙指縮放手勢同樣停在視窗上：捲過清單的盡頭也絕不會捲動到遊戲。
  • 不經過控制項的遊戲輸入 — 用來移動的 _unhandled_input、拖曳鏡頭 — 應該暫停： if GoSurface.is_any_open(): return。這涵蓋了對話方塊、底部面板、錨定卡片與組合方塊；抽屜則要另外問它的 is_open()。
  • 訊息條、提示條、提示卡片與導覽標記只在它們自己的卡片上接收輸入；其他地方的輸入都交給遊戲。

焦點

用指標打開的視窗不會把焦點放在任何東西上 — 觸控時不會閃出焦點框。用鍵盤或遊戲手把打開時，關閉按鈕 （或 initial_focus）取得焦點。視窗開著時焦點留在視窗裡，關閉後回到原本握有 焦點的那個控制項。對話方塊每次都會把焦點放在確定按鈕上。

暫停遊戲

暫停場景樹也會暫停彈出視窗 — 只有主控台照常運作。做暫停選單時，請替它的圖層設定 process_mode = PROCESS_MODE_ALWAYS；這樣遊戲停下來時，視窗、它的按鈕與返回鍵都會繼續運作。

func pause() -> void:
    get_tree().paused = true
    var layer := CanvasLayer.new()
    layer.layer = 50
    layer.process_mode = Node.PROCESS_MODE_ALWAYS      # 遊戲暫停時也繼續執行

常見陷阱

  • GoSurface 從不自己釋放。請連接 close_requested，否則按 × 不會有任何反應。
  • 在 add_child 之後才設定的選項 — scrim_transparent、show_header、resizable、 scroll_body，以及 GoDialogs 的 layer_index 與 max_width — 都不會套用。
  • 第二個 confirm() 會立刻回傳 false。如果兩個問題可能撞在一起，請打開 queue_when_busy。
  • Enter 會確認。焦點在確定按鈕上，破壞性對話方塊也一樣。
  • 底部面板上的返回鍵會關閉整個底部面板，而不是退出子頁面。
  • Esc 不會關閉抽屜，而且 is_any_open() 也看不到它。
  • 錨定卡片或組合方塊的清單會擋住遊戲，直到它關閉為止，即使遮罩是透明的 — 而一張 dismissable = false 又沒有標題的錨定卡片，畫面上沒有任何東西能關閉它。
  • 提示卡片一開始是隱藏的，而且沒有逾時。
  • seconds: 0 又沒有按鈕的訊息條永遠不會離開。而且預設情況下，它會接住落在卡片上的點按。
  • 沒有人知道的長按，就是沒有人用的功能。請同時顯示一個 ⋯。
  • 場景樹暫停時，你的彈出視窗也會暫停。請替它的圖層設定 PROCESS_MODE_ALWAYS。
  • 沒設寬度的提示條會縮到最窄 — 請用 preferred_width()。
  • 絕不在訊息條裡發問，絕不用對話方塊發通知。問題被忽略就消失了；消息則不該讓遊戲停下來。
