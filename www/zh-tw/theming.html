佈景主題

gohud 的外觀分成三層。可以只換顏色，也可以整個換掉形狀。

三層

一個預設集把三層綁成一組。留空的欄位會退回使用預設值。

層決定什麼怎麼改
Theme 顏色、尺寸、文字比例，以及引擎畫出來的一切的形狀 — 按鈕面板、輸入欄、分頁、切換開關的圖檔 自己寫一份 .tres，或用 tools/make_theme.py 產生一份
GoSkin 程式碼畫出來的一切的形狀 — 搖桿、快捷格的面、導覽標記的圈、標籤片、骨架佔位、分隔線、區段標題 繼承它，只覆寫你在意的那幾個方法
GoIconSet 用名稱取用的圖示 — 84 張預設圖案，或中世紀組疊在上面的 16 張雕刻圖案。可以是材質包，也可以是圖示字型；呼叫端的程式碼兩種都一樣 換上一整組，或只覆寫其中幾個名稱
為什麼光有 Theme 不夠。StyleBoxFlat 只有圓角這一種角 — 把半徑設成零就變直角；中間什麼都沒有。斜切的角、單獨一道加粗的邊、外側的光暈：引擎一個都畫不出來。 而搖桿與導覽標記是在 _draw() 裡畫的，佈景主題根本伸不進去。

挑一個

GoUi.use_preset(GoThemePresets.SCIFI_DARK)

這一行就換掉佈景主題、外觀與圖示。從編輯器要挑的話，用 專案設定 → Gohud → Theme → Preset；從設定資源則是 GoConfig.preset。

只留一個欄位給自己

GoUi.use_preset(GoThemePresets.SCIFI_DARK)
GoUi.config.icons = my_icons     # 圖示用你的，其餘全部用預設集的

明確設定 theme、skin 或 icons 會蓋過預設集。

內建的六種預設集

預設集面板外觀 · 圖示
default_dark · default_light圓角的 StyleBoxFlat 面板，搭配分級的陰影刻度；主要按鈕會浮起，按下時沉下去GoSkin · 84 個預設圖示
scifi_dark · scifi_light切角的 GoStyleBoxCut 面板，帶霓虹邊與光暈；焦點記號用 GoStyleBoxBracketGoSkinSciFi — 六邊形搖桿 · 預設圖示
medieval_dark · medieval_light鍛造的 GoStyleBoxMedieval 框 — 鐵與皮革，或羊皮紙 — 選單上還有鉚釘與角落裝飾GoSkinMedieval · 16 個雕刻圖示疊在預設之上

中世紀：鐵、皮革與羊皮紙

medieval_dark 把暗鐵與皮革配上古金色。medieval_light 用的是羊皮紙與墨水。兩者都用 GoSkinMedieval、現有的控制項，以及 16 個帶雕刻細節的 原創圖示；導覽類圖示則退回使用原本那一組。

GoUi.use_preset(GoThemePresets.MEDIEVAL_DARK)
# 或：GoUi.use_preset(GoThemePresets.MEDIEVAL_LIGHT)

要在建立 UI 之前挑好預設集。明確指定的 GoConfig.theme、 skin 或 icons 依然優先。開啟 res://addons/gohud/examples/medieval/medieval.tscn 並按 F6，就能看到可運作的 角色面板、行囊與任務日誌。裡面的按鈕會切換變體，也會打開物品細節。

選單框上有一顆鉚釘與一小塊角落裝飾；始終顯示的 HUD 則保持安靜的邊。 生命、魔力與體力分別用紅、藍與橄欖綠填色。Cinzel 只用在標題與副標題； 內文文字維持宿主／預設字型。內附字型的授權放在 assets/fonts/cinzel/OFL.txt。

雕刻組重畫了 bag、book、box、coin、crown、 flag、heart、key、map、potion、shield、 star、sword 與 user，另外加上 scroll 與 seal。 其他每一個名稱都退回預設組，所以 close 與 settings 在每一種預設集裡都維持原本的 圖案。Cinzel 只涵蓋拉丁字母；在地化的標題請透過 shape.fonts 指定自己的字型。

測試套件對兩種變體檢查了什麼。中世紀外觀有被選用；選單與 HUD 面板是鍛造框，而裝飾只出現在選單上； 標題使用 Cinzel，內文則沿用繼承來的字型；雕刻圖示以 DPITexture 匯入；實際的快捷格有用到該外觀； 改動複製出來的外觀的旋鈕，效果會傳到快捷格而不必更動預設集；切換回去時，預設與科幻的幾何形狀都能復原。

打造一個自己的王國

python3 addons/gohud/tools/new_theme.py kingdom --from medieval_dark
# 編輯 themes/palettes/kingdom.json，然後：
python3 addons/gohud/tools/make_theme.py kingdom
godot --headless --path . --import
# 在 GDScript 中，建立控制項之前：
GoUi.use_preset(&"kingdom")

JSON 佈景主題可以繼承其他 JSON 佈景主題。省略的值沿用上層的設定； 循環繼承會被拒絕。產生出來的預設集會保留上層的圖示組。

設定效果
shape.material0：鐵 · 1：皮革 · 2：羊皮紙。控制表面的紋路。
shape.grain_alpha紋理的不透明度。想要乾淨的表面就設成 0。
shape.ornament_scale · shape.bevel_strength選單角落裝飾的大小，以及斜角高光的強度。
shape.fonts把 title、subtitle、caption、body 與 button 這幾個角色對應到附加元件本地的 res:// 字型檔。省略的角色沿用繼承來的字型。
skin.dials快捷格圓角、鉚釘顯示與否、紋理與高光。下面的完整表格列出每一個旋鈕。

Token

每一個顏色與尺寸都放在 Theme 裡的 GoHud 型別底下，用名稱取用。 規則就是不寫數字：換掉佈景主題時，名稱會跟著走。 

GoUi.color(GoTheme.ACCENT)             # 顏色
GoUi.metric(GoTheme.GAP)               # 尺寸（dp）
GoUi.font_size(GoTheme.ROLE_CAPTION)   # 某個文字角色的大小
GoUi.box(GoTheme.BOX_CARD)             # StyleBox 的副本

文字角色

micro · compact · caption · body · button · subtitle · title — 一個角色指的是一種大小， 而不是一種用途。是「最大的文字」，不是「標題」。這樣即使某個畫面拿它來做別的事，整套比例仍然成立。

StyleBoxFlat 畫不出來的形狀

類別畫得出什麼
GoStyleBoxCut斜切的角、一道加粗的強調邊、外側光暈
GoStyleBoxBracket只有角落的記號，不把內容框起來

這三種都能像其他 StyleBox 一樣序列化進 Theme 資源 — 這正是佈景主題改得了形狀的原因。

內距要透過 content_margin_* 給。在 GDScript 裡繼承 StyleBox 時， _get_style_margin() 永遠不會被呼叫（在 Godot 4.7 上實測）。請填好內建欄位， 否則內容會貼在邊框上。

你自己的預設集 — 一個檔案

以前要加一份佈景主題，得手動改四個地方 — 產生器的調色盤、形狀、一份外觀、一個預設集資源。 現在一道指令就把它們全部就位。 

python3 addons/gohud/tools/new_theme.py neon --from scifi_dark --title "Neon"
python3 addons/gohud/tools/make_theme.py neon      # 佈景主題 .tres + 控制項圖檔
godot --headless --path . --import                  # 把新圖檔匯入一次
GoUi.use_preset(&"neon")                             # 完成 — 選擇器裡也會出現

第一行會寫出 themes/palettes/neon.json 與 themes/presets/neon.tres。這份 JSON 會把它所繼承的佈景主題的每一個值都完整寫出來，所以它同時就是一份「可以改什麼」的清單： 刪掉一個鍵就沿用上層的值，寫上去就覆寫它。預設集是靠掃描 themes/presets/ 找到的，所以不用改任何註冊用的程式碼 — 專案設定的下拉選單也會自動抓到。

繼承外觀（選用）

只有佈景主題與形狀碰不到的東西 — 搖桿的六邊形、快捷格徽章、導覽標記的 瞄準框角 — 才住在外觀裡。繼承 GoSkin，只覆寫那幾個方法，再把 JSON 的 skin 指向那份資源。只改顏色的佈景主題可以略過這一步。

有一項檢查替這個承諾把關。tools/check_scaffold.sh 每次執行都會建立一份用完即丟的佈景主題 — 改掉強調色、把圓角半徑設成 4 — 並在刪掉它之前驗證產生、token 傳遞與乾淨的對比檢查。 第一次跑就抓到：只改了強調色的佈景主題有8 組配色不合格 — 產生器推了文字顏色， 卻照著原樣使用強調色。現在連強調色與疊在它上面的標籤也一起推。

可讀性是量出來的

「好看」是品味；「看得清楚」量得出來。淺灰色的文字在好螢幕上看起來沒問題， 到了白天的手機上就消失 — 用眼睛挑，遲早會走到這一步。 

python3 addons/gohud/tools/check_contrast.py
項目要求
內文文字4.5 : 1
大字（24px 以上）3 : 1
強調色的邊框與圖示3 : 1
裝飾性邊框2 : 1 — WCAG 不把 3:1 的規則套用在裝飾上
相鄰的面1.12 : 1 — 足以讓卡片看起來和背景是分開的

同色相的文字疊在同色相的著色上

這個陷阱在這套程式碼裡出現了三次 — 按下狀態的按鈕（強調色面板配強調色標籤）、 危險按鈕，以及標籤片。它在色票上看起來很好，一量就垮，因為兩者色相相同，明度自然沒有差別。

所以標籤顏色不是手挑的。佈景主題產生器與 GoSkin 各自 推動明度 — 而且只推明度 — 直到在文字實際落腳的那塊面板上達標為止。色相與飽和度保持不變， 所以調色盤維持它的個性，換了調色盤對比也還在。

當成文字讀的顏色，和當成面積塗的顏色，要的東西相反

在淺色佈景主題上，警告色必須變深才能當成文字讀得清楚（#96500A）。 量條的填色如果直接繼承它，經驗量條就會變成咖啡色。光靠顏色解決不了： 黃色本來就亮，在完全沒有灰色軌道的情況下就能過 3:1，而把軌道加深只會更糟（1.52 → 1.06）。

所以兩者被分開了。顏色保持鮮豔 — 調色盤帶有只用於填色的顏色，例如 warning_vivid。對比交給邊緣 — GoSkin 會在任何無法對軌道 達到 3:1 的填色上畫一道 1dp 外框，讓「現在裝了多滿」依然看得清楚。 

MY_LIGHT = dict(
    warning=hexc("9A5407"),         # 當成文字讀
    warning_vivid=hexc("F2A007"),   # 塗在量條上
)
漏掉會被回報。少了 *_vivid，填色算出來偏暗時，產生器就會印出 막대가 칙칙하다 — 팔레트에 warning_vivid 를 더한다（產生器實際輸出的字句， 意思是「量條變得灰暗 — 請在調色盤裡加上 warning_vivid」）。以前會默默劣化的地方，現在會出聲。

浮動面板不知道背後是什麼

HUD 是畫在遊戲之上的 — 可能是一片雪原，也可能是一個洞窟。如果它的面板是半透明的， 背後的東西就會透出來並改變面板的顏色，連帶把文字對比拉下去。 在 82% 不透明度下，深色佈景主題的淡化文字疊在明亮背景上只剩 3.74:1 — 低於下限。

所以半透明面板是拿純白與純黑墊在背後量的；那是遊戲場景所能給出的最糟情況。 內附佈景主題的 HUD 面板夠不透明（92%）而能過關，同時保住那層玻璃感。

基於同樣的理由，圖示顏色也不是寫死的。快捷格的圖形原本被寫死成白色， 在淺色佈景主題上量出 1.11:1 — 現在它會跟著所在的面板走，和標籤完全一樣。

兩個檢查器，兩種觸及範圍。check_contrast.py 讀的是佈景主題檔； 外觀在執行期間混出來的顏色（標籤片、快捷格）則由測試套件在 Godot 裡的 skin contrast 區段量測。
