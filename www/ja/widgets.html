ウィジェット

どれも .new() して add_child() するだけだ — シーンファイルもオートロードもいらない。 🛑 の付いた注記は、机上の話ではなく実機の画面でぶつかった落とし穴だ。

浮かぶウィンドウ

GoSurface — 外殻

ポップアップもシートもドロップダウンも、すべてこれ1つを使う。セーフエリア、仮想キーボード、 固定ヘッダーとフッター、スクロールする本文、どのウィンドウが最前面か、フォーカスの復帰、 戻るボタンの所有権、ドラッグでのサイズ変更まで面倒をみる。

配置見え方用途
CENTER中央のカード確認、設定
BOTTOM下からせり上がるシートリスト、管理画面
ANCHORコントロールの脇に留まるカードドロップダウン、コンテキストメニュー
自分では消えない。 close_requested を受けて隠すか解放するかは、持ち主である画面の仕事だ。 外殻にはなぜ閉じようとしているのか（保存して閉じるのか、破棄するのか）が分からないからである。

GoSheet — 下から出るページ

var sheet := GoSheet.new()
add_child(sheet)
sheet.open("インベントリ")
sheet.toolbar().add_child(GoStyle.line_edit("検索…"))
sheet.toolbar().visible = true
sheet.footer().add_child(GoStyle.button("閉じる", sheet.close, GoStyle.Tone.PRIMARY))
sheet.footer().visible = true

自前の CanvasLayer を持つので、HUD より確実に上に出る。open() は本文を空にし、 戻るボタンと固定行をいったん無効にする — 戻る先のない画面で死んだボタンが見えていると、 壊れているように読めるからだ。

GoDialogs — await で受け取る確認

if await dialogs.confirm("セーブデータの削除", "元に戻せません。"):
    delete_save()

confirm(title, body, ok_text, cancel_text, extra, args, destructive) — 本文より後ろはすべて省略でき、 alert() はボタン1つで同じように使える。取り消せない操作には destructive を立てる。 確認ボタンが塗りつぶしの GoStyle.Tone.DANGER_SOLID になる。ライトテーマでは、淡く色を付けた危険ラベルは 黒い文字に見えるまで暗くするしかないが、塗りつぶしのボタンなら赤地に白文字を保てる。ウィンドウは1つを使い回すので トーンは呼び出しのたびに付け直され、1つ開いている間に2つめの confirm() を呼ぶと即座に false が返る。confirm_key() は翻訳キーを受け取る。

ボタンの並べ方。 action_layout の既定は VERTICAL（長い訳文でも安全だ）、 HORIZONTAL なら半分ずつの幅で1行に、AUTO なら両方のラベルがカードの半分に1行で 収まるときだけ横に並べ、収まらなければ縦に積む。action_gap はボタンどうしの間隔、 body_gap はその上の間隔だ — ボタン間より広くとると、問いと選択肢が2つの塊として読める。 1つのダイアログにだけ効かせたいときは、開く前に set_next_action_layout() を呼ぶ。 ボタンの行は最初にダイアログを開いたときに組み立てられるので、オートロードした GoDialogs でも 起動時のコストはない。

GoForm — 幅に上限のあるフォーム

配下のラベルが必ず折り返すことを保証する。 これがないと、長い一文が1行に伸びて最小幅が画面を超え、 左右が切れる — 自分がどの画面にいるのかすら分からなくなる。シーンごとに手で折り返しを有効にする方法は、 毎回必ず忘れられる。

GoScroll — タッチでのスクロール

中に入れるのは1つだけにする。見出しやボタンの行は外側だ — 長いリストがそれらを画面外へ 押し出してはならない。use_panel_edge() は、中身のインデントを保ったまま スクロールバーをカードの既存の余白へ移す。

プレイヤーに何かを伝える

GoNotice — スナックバー

入力を横取りしない。 通知は読むものであって、押すものではない。フォーカスを取らず、ゲームの入力も 塞がず、その下のボタンはそのまま押せる。確認が要るなら GoDialogs、選択が要るなら GoPromptCard を使う。

GoPromptCard — 画面を塞がない問いかけ

幕を張らずに片側へ浮かぶ。ゲームは動き続ける。

GoCoachMark — ガイドツアー

実物のコントロールを1つずつ指し示す。入力を受けるのはカードだけなので、強調されたコントロールを 押すこと自体がツアーを進める — 「ここを押してください」が文章ではなく操作になる。

tour.start([
    {"target": bag_button, "title": "かばん", "body": "拾ったものはすべてここに入る。"},
    {"target": map_button, "title": "マップ", "body": "押すと全体マップが開く。"},
])

title と body には翻訳キーでも、そのままの文字列でも渡せる。 対象が消えてしまったステップは飛ばされる。

HUD

出来を決めるのは小さなところだ

大きなパネルをいくら磨いても、目に留まるのはいつも小さなものだ — 途中で切れた単語、欠けた発光、 窮屈なスロット。2026-09-13 にそうした4つが指摘され、デモ画面ではなくウィジェットとテーマの側で直した。 だから、どの画面でも同じ結果になる。

何が起きたか原因直し方
コーチマークの Done が Don/e になった 折り返しを有効にしたボタンは文字幅を最小幅から差し引く — 狭められると単語の途中で割れる GoStyle.fit_words(): 1単語なら決して折り返さず、複数語なら折り返すがいちばん長い単語は必ず収まる。判定は翻訳キーではなく実際に表示される文字で行い、言語が変わればフォームが付け直す
全幅ボタンの発光が、左側だけ縦に切れた スクロールコンテナは例外なく自分の端で切り取る。右だけはレールの余白のおかげで残っていた GoScroll が親の余白を借りて端を 12dp 外へ押し出し、内側で返す — 中身の位置は動かない
スロットの中で、時間・アイコン・個数が縦に積み上がった 48dp の中に3行あった アイコンは中央に大きく、ショートカットは左上、個数は右下のバッジ、残り時間はアイコンに重ねたバッジへ — バッジのパネルはスキンの badge_box() から来る
ドロップダウンが平坦で、どれを選んでいるか見えない 項目のホバーにボタンのパネルを使い、ラジオの印はエンジンの薄い既定のままだった 専用のホバーパネル（淡いアクセント）、チェックボックスと同じラジオの絵、タッチに合わせた項目の高さ

アイコンだけのボタンには GoStyle.icon_button(icon, action, -1, tooltip_key) で説明を与える — マウス利用者へのツールチップも、スクリーンリーダー向けのアクセシビリティ名も、この1つの値から取る。 ツールチップは gohud が自分で描く。エンジンの既定は、幅の計算が狂うと文字を1文字ずつ改行してしまう （幅 1dp と実測された）。

コーチマークのカードは固定物を避ける

横持ちでは、カードが画面のいちばん上か下の端へ送られていた — ヘッダーや HUD がちょうど居座る場所だ。 デモではヘッダーの → × の上に重なっていた。いまは対象と同じ高さにとどまり、場所を確保している GoHudAnchor を回り込み、そのほか避けたいものは keep_clear で受け取る。 対象を覆わずに障害物から外れる最短の距離だけ動き、画面が狭くてすべてを避けきれないときはその場にとどまる — 重なるほうが、消えるよりましだ。ページより上にあると読めるだけの立体感は、スキンのダイヤルから来る (float_shadow_size、float_shadow_lift、float_shadow_alpha。面取り系のスキンは float_glow_size)。 

tour.keep_clear = [header_bar, toolbar]   # アンカーではない固定物

マウスとキーボードのある画面

指にはホバー状態がない。 モバイルだけを見て作ると、デスクトップにしかない2つの状態が未確認のまま残る — そして実際、片方は壊れていた。gohud のフォーカスリングが主ボタンの上で見えなかったのだ。パネルが アクセント色で、リングも同じ色。1.00:1、同じ色を同じ色の上に描いていた。キーボードで移動すると、 自分がどこにいるのか分からなかった。

塗りつぶしのボタン（GoPrimaryButton、GoDangerSolidButton）は 自分のパネルと対比するリングを使う — ダークテーマでは暗く、ライトテーマでは白く、SF では暗い照準 ブラケットになる。コントラスト検査はフォーカスリングを、それが載っているパネルに対して測るので、 パレットを変えてもこの規則は生き残る（WCAG 2.4.11 はフォーカス表示に 3:1 を求めている）。

HUD ウィジェット

GoHudAnchor — 9か所

セーフエリアと画面端の余白を尊重する。landscape_spot を与えれば横持ちで移動する — 縦持ちで下中央にあるコントロールを、横持ちでは右下へ回せる。

なぜ必要か。 HUD ごとに手で書いたアンカーとオフセットは必ずずれていく。ノッチのある端末では体力バーが カメラの切り欠きの下に入り、横持ちでは操作ボタンがジェスチャーバーの上に載る。その算術を1か所に集めてある。

本文を HUD の下に潜り込ませない

スクロールする画面が HUD と同じ表示面を分け合うと、本文はその下へ滑り込み、2組の文字が重なって どちらも読めなくなる。このアドオンでも2度起きた。入力欄のプレースホルダーがクイックスロットの間から はみ出し、設定のトグルのつまみが体力バーの上に載った。 

form.avoid_hud = true                  # 表示中の GoHudAnchor をすべて避ける
joystick_anchor.reserve_space = false  # …指が触れたときだけ現れるものは除く

それぞれの矩形は失う面積がいちばん小さい方向へ避ける。右上のバーは、縦持ちのスマートフォンでは下へ 回り込み（高さの 13%）、横持ちでは横へ回り込む（幅の 21%） — 横持ちで縦に避ければ画面の 27% を失う。 すでに明け渡した領域は、次の矩形を測る前に差し引かれる。

HUD どうしもぶつかる

9か所は画面を分割するだけで、部品どうしがぶつからないことまでは保証しない。上中央の幅広い スナックバーが、右上の体力バーの真上に着地して値を隠した — 残り体力が読めなかったのだ。 

notice_anchor.avoid_peers = true      # 固定 HUD の下へ落ち着く
notice_anchor.reserve_space = false   # 出ている間にページを押しのけたりはしない

よけるのは縦方向だけだ — 横にも動かすと、中央揃えのトーストが出るたびに違う場所に現れてしまう。 しかも、避けるのは自分からはよけない部品に対してだけだ。両方が譲ると、2つは永遠に場所を入れ替え続ける。

GoBar — 体力・マナ・経験値

var hp := GoBar.new()
hp.label_text = "HP"
hp.ink = GoUi.color(GoTheme.DANGER_FILL)   # 塗り専用のトークン
hp.set_values(320, 500)                     # "320 / 500"

変化は 0.18 秒かけてなめらかに動く — 跳ねる体力バーは、どれだけ強く殴られたのかを伝えない。 reduce_motion にすれば即座に反映する。大きな数は 12.3k のように略記するので、 桁が増減してもバーの幅が揺れない。

GoSlot — クイックスロット1つ

アイコン、個数、クールダウン、ショートカットを1つの面に収める。小さな円にバッジをぶら下げると、 スロットごとに幅が変わって列が揺れてしまう。

見える大きさと押せる大きさは違う。 詰めて並べたスロットは 48dp のタッチ領域が重なる。重なった分は 中心が近いほうのスロットが取る — touch_peers で互いの存在を教えておく。

keyboard_focus は既定で無効だ。8個並んだスロットが、キーボード利用者と設定項目すべての間に Tab 順で割り込まないようにするためである。キーボードやゲームパッドが唯一の入力手段なら有効にする。

GoJoystick — バーチャルスティック

モードふるまい
FIXED常に同じ場所 — 見なくても指が届く
FOLLOW親指を置いた場所に現れる
RELATIVE現れたあとも親指を追い続ける — 長く動かすときに楽だ

moved が渡す Vector2 は長さ 0〜1 なので、そのまま速度に掛けられる。 画面サイズや DPI で変わることもない。

GoIconButton — 小さく見えて大きく押せる

安全なのは、隣が入力を受け取らないときだけだ。 広げた領域が隣のボタンに重なると、そのボタンは 反応しなくなる。並べて置くアイコンボタンには touch_peers が要る。

待たせる、伝える、数える

GoSnackbar — 自分で居場所を決めるメッセージ

画面の下（あるいは上）に、セーフエリアと仮想キーボードを避けて出て、自分で消える。これがないと、 「保存しました」と言うだけの画面ごとに、レイヤーも配置もタイマーも後片付けも書くことになる。

snack.show_text("保存しました", GoTheme.SUCCESS)

# 取り消す機会 — 0 は最初のボタン、-1 は時間切れ
if await snack.post({"text": "アイテムを捨てた", "actions": ["取り消す"]}) == 0:
    restore_item()

メッセージは互いを上書きせず順番に並ぶし、同じ文面の繰り返しはまとめられる — 毎秒4回失敗する サーバーが、4分ぶんの警告を積み上げることはもうない。ボタンのないスナックバーは入力を通すので、 その下のゲームは動き続ける。

何かを尋ねる場所ではない。 自分で消えてしまうので、プレイヤーが一度も見ないことがある。 取り消せない操作の確認は GoDialogs の仕事だ。ここに置くボタンは、なくても困らないものに限る — 取り消す、詳細、再試行。

GoNotice はこの対のもう半分だ。入力もフォーカスも決して取らず、どこに出すかは持ち主の画面が 決める。あちらはボタンを持てないが、こちらは持てる。

GoSpinner — 終わりの見えない待ち時間

サーバーと話すゲームが、このページの中でいちばん必要とするものだ。止まったままの画面は、落ちたと 読まれる。呼び出し1つで、押されたボタンがその場でスピナーに変わる。

GoSpinner.busy(buy_button, true)
var ok := await server.purchase(item)
GoSpinner.busy(buy_button, false)

ボタンは大きさを保つ — ラベルは消えるのではなく透明になるので、行が跳ねない — そして回っている間は 無効になる。要はこの後半だ。await している間に購入が2回走ってはならない。 reduce_motion にすると回らず、代わりに3つの点が明滅する。

測れる進捗なら GoBar だ。スピナーは、いつ終わるかを何も約束しない。

GoBadge — 未読の点、NEW の札、99+

GoBadge.attach(mail_button, unread_count)   # 0 のときは自分で隠れる
GoBadge.attach(shop_button, 0, "NEW")
GoBadge.attach(friend_button, 3, "", true) # 点 — 「何かある」

アンカーで持ち主の右上に吊り下がるので、大きさが後から決まる相手にも付いていくし、2度付けても同じ バッジが返る。数が変われば行動も変わるときは数字を、「何かある」ことだけが問題なら点を使う。

文字の色は、スキンがバッジをどの色で塗ったとしてもコントラストが取れるように選ばれる — 白だと決めて かかることはない。読み上げ用の名前も持つ。色の付いた点は、スクリーンリーダーには何も伝えないからだ。

フォームとリスト

GoField — 間違いを抱えられる行

入力欄が5つあるフォームの先頭に「入力を確認してください」と1行あっても、どの欄なのかは分からない。 その1点だけで、人は新規登録をやめてしまう。

var name_field := GoField.make("キャラクター名", GoStyle.line_edit("2〜12文字"), "あとから変更できない")
name_field.set_error("その名前は使われている")   # サーバーが断った
name_field.clear_error()

エラーが出ている間ヒントは隠れるので、行が1行ぶん伸びて下のすべてを押し下げることがない。エラーの文は コントロールの読み上げ名にも連結される — 赤い枠だけでは、赤が見えない人には何も伝わらない。

GoStyle.field() は静的な版だ。ラベル、コントロール、ヒント、エラー状態なし。何も失敗しよう がないところはファクトリで、サーバーに断られうるものはノードで作る。

GoInputGroup — ボタンと溶接された入力欄

GoInputGroup.make(GoStyle.line_edit("メッセージ"), {"suffix": GoStyle.icon_button(&"send", send)})
GoInputGroup.make(GoStyle.line_edit("名前"), {"prefix_icon": &"search"})

これが解くのは角の問題だ。丸い形が2つ真ん中で出会うとくびれて見えるし、既定の隙間があると2つの物体と して読めてしまう。外側の角は丸いまま、触れ合う角は四角にする — それをボタンのどの状態でも行う。さもないと、 押した瞬間にグループが割れる。面取りのスキンにはそもそも角の項目がないので、そこでは何も触らず、四角い 面どうしがきれいに合わさる。

GoCombobox — 検索できるピッカー

項目が10個までなら GoStyle.select() のほうがよい。タップが1回少なく、リスト全体が見える。 30 を超えると、目で追うこと自体が作業になる。

var picker := GoCombobox.make(server_names, 0, "サーバーを選ぶ")
picker.picked.connect(func(i: int) -> void: connect_to(servers[i]))
検索は名前の先頭だけでなく、途中にも一致する。 前方一致では、日本語や韓国語のリストはほとんど 引っかからない。2つの項目を見分ける語が先頭に来ることは、めったにないからだ。

GoCodeInput — クーポンとギフトコード

コードは打ち込まれるより、メッセージから貼り付けられることのほうがずっと多い。本物の入力欄を12個並べると、 貼り付けは最初のマスで止まり、IME が文字を食う。だから文字を受け取るのは隠した1つの欄で、マスは描かれた ものだ。ABCD-EFGH-IJKL は、入るときにハイフンが落ちる。

var coupon := GoCodeInput.make(12, 4)
coupon.completed.connect(func(code: String) -> void: server.redeem(code))
coupon.set_error("使用済み")

GoTable — 並べ替えできる見出し、選べる行

var board := GoTable.make(
    [{"text": "順位", "width": 56}, {"text": "名前"}, {"text": "スコア", "numeric": true}], rows)
board.row_selected.connect(func(i: int) -> void: open_profile(rows[i]))
numeric: true を忘れると、順位が逆さになる。 文字として比べると "9124" が "91240" に勝つ — スコアも所持金もダメージも、桁数はばらばらだ。

row_selected が渡すのは、並べ替え後の位置ではなく元の配列での添字だ。並べ替えの向きは色だけで なく記号でも示され、行は全体が押せるので、1つのセルを狙う必要はない。GoStyle.table() は 読み取り専用の表のまま残る。

GoPagination — ページ番号、あるいは「もっと見る」の行

var pager := GoPagination.make(1, 12, func(page: int) -> void: load_mail(page))
var more := GoPagination.more(load_next)   # スマートフォン向きの変種

番号はマウスの UI だ。スマートフォンなら「もっと見る」の行のほうが読みやすい。現在のページは窓の中央に 留まるので、次を押すたびに番号が全部並び替わることはない。合計 0 は「不明」を意味し、矢印だけが描かれる — 渡されていないページ数を、勝手に作り出したりはしない。

ゲームで実際に使う形

見慣れたウェブの形を、ゲームがそこに求めるものを軸に作り直したものだ。

GoRewardCalendar — 毎日のログインボーナス

日付ピッカーがゲームで役に立つことは、ほとんどない。カレンダーの形は役に立つ — ログインボーナスだ。 そこで問題になるのは何日目かであって、何月何日かではない。

var attendance := GoRewardCalendar.make(days, claimed_until)
attendance.claimed.connect(func(day: int) -> void: server.claim_day(day))

押せるのは今日のマスだけだ — 押しても何も起きないボタンは、壊れていると読まれる。受け取り済み・今日・ これからの3つは、同時に3つの違いで見分けられる。チェックの記号、強調色の枠、そして暗さだ。

GoRadar と GoDonut — ひと目で分かるステータス

var stats := GoRadar.make({"STR": 0.85, "AGI": 0.5, "INT": 0.3, "VIT": 0.7, "LUK": 0.45})
stats.set_compare(with_new_sword)          # 破線の重ね描き

var share := GoDonut.make([{"label": "物理", "value": 620}, {"label": "魔法", "value": 340}])
card.add_child(share.legend())

レーダーの値が 0〜1 なのは、どこを満点とするかがゲームの決めることだからだ — 素の STR 120 を INT 45 の 隣に置けば、嘘の形が描かれる。ドーナツの値は素のままでよく、割り算はこちらでやる。5つを超えた分はまとめ られる。6枚目の扇形は、誰にも読めない糸になるからだ。比較の線は色違いではなく破線で、凡例には 割合が文字で出る。

GoCarousel — バナーとキャラクター選択

banners.set_pages([promo, event, pack])
banners.autoplay_seconds = 5.0             # 既定では動かない

頼まない限り自分では進まないし、5秒が下限だ。3秒ごとに変わるバナーは、読み終える前に文字を持ち去る。 触れるとタイマーは戻り、reduce_motion にすれば自分から進むことは一切ない。点は小さく描かれる が、押せる範囲はタッチの最小寸法を保つ。

GoKbd — 嘘をつかないキー表示

hint.add_child(GoKbd.for_action(&"interact"))   # 実際の割り当てを読む

直接書き込んだ「F を押す」は、プレイヤーが割り当てを変えたあとも F と言い続ける — PC の UI でいちばん よくある嘘だ。for_action() は InputMap を読む。その操作がパッドに割り当てられて いれば空を返してウィジェットは隠れる。「なし」もまた1つの嘘だからだ。Android と iOS では自分から隠れる。

画面の上に重ねる

GoDrawer — 横から出るパネル

GoSheet は下から出る。縦に持ったスマートフォンにはそれが正しい。タブレットやデスクトップでは、 同じシートがゲームを覆ってしまう。ドロワーは代わりに横から出る。

bag.side = GoDrawer.Side.RIGHT
bag.open("かばん")

パネルは画面の端まで届くが、中身はセーフエリアの内側に留まる。そうしないと、丸めた角が最初の行を切り 落とす。LEFT はアラビア語でも画面の左だ。「始まりの側」であることが要点なら follow_text_direction を有効にする。RTL では左右が入れ替わる。

GoPopover — 脇に留まるカード

GoPopover.open(slot, item_card(item))

GoSurface の脇に留まる配置に、レイヤーもサーフェスもアンカーも後片付けも配線済みの ものだ — どのゲームも何度も書く、あの10行である。開くのは一度に1つだけだ。カードが積み重なると画面が埋まり、 どのカードがどのスロットのものか分からなくなる。幕は透明だ。装備を見比べるために開いたカードが、その装備を 暗くしてはならない。

ホバーのツールチップではない。 タッチにホバーはない。マウスでしか現れないものは、プレイヤーの半分 には見えないままだ。

GoContextMenu — 長押しと右クリック

GoContextMenu.attach(item_slot, [
    {"text": "使う", "action": use},
    {"separator": true},
    {"text": "捨てる", "action": drop, "danger": true},
])

PopupMenu はエンジンにすでにある。ないのはジェスチャーのほうだ。開くまで 0.5 秒、 指が動いた瞬間に取り消す。だからリストをスクロールしてもメニューは出てこない。項目が「どれを押したか」 で変わるなら、配列の代わりに Callable を渡す。

長押しには、もう1つの入り口が要る。 隠れたジェスチャーは誰にも見つけられない — 目に見える ⋯ ボタン（open_at()）や、アイコンや、初回のコーチマークと組み合わせる。

GoConsole — 開発者コンソール

console.register("give", "アイテムを与える: give <id> <count>", give)
console.toggle()

チートとデバッグのコマンドだ。打つそばから絞り込むパレットが付くので、覚えておく必要はない。履歴は 矢印キーに載っている。すべての上に出るので、ダイアログの上からでもデバッグできる。

リリースビルドでは開かない。 debug_only は既定で有効だ。チートコマンドがプレイヤーの手に 渡れば、ゲームの経済は初日で終わる。

Button.new() を直に呼ぶと、余白も高さも折り返しも画面ごとに少しずつずれていく。 そのずれはコードレビューでは見えず、スクリーンショットでは一目で分かる。

説明の付いたリスト行

GoStyle.list_button(GoIconSet.SWORD, "誓いの剣", _inspect, Color.TRANSPARENT,
    "ロングソード  /  攻撃力 42", false)

2行目のある行は上下の余白が等しくなり、1行の行より広めにとられる。タイトルと説明の組は アイコンの脇で上下中央に保たれる — コンテナが行を縦に引き伸ばしたときも、説明が複数行に折り返した あとも同じだ。行全体は1つのタップ対象のままである。

折り返して流れる行

コントロールは自然な幅のまま wrap_row に入れる。折り返しを有効にしたままだと、 ボタンの最小幅はほとんど 0 まで落ち、行はその値でセルの大きさを決めてしまう — ラベルが1文字ずつ改行される。 ファクトリがこれを防いでくれる。

空のリストを空のまま見せない

page.add_child(GoStyle.empty_state(GoIconSet.BOX, "まだ何もない"))

人は何もない画面を壊れていると読む。
