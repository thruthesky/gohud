ポップアップとダイアログ

gohud のすべてのポップアップ — どれを選ぶか、どう開いて閉じるか、戻る操作と入力に何をするか、すべての見た目で。 ← ウィジェット

ウィジェット すべてのウィジェット ポップアップとダイアログ 浮かぶウィンドウ プレイヤーに何かを伝える HUD 待たせる、伝える、数える フォームとリスト ゲームで実際に使う形 画面の上に重ねる GoStyle — 作る場所を1つにする

ふさわしいポップアップを選ぶ

ポップアップは流れを断ち切る。選ぶ前に、ひとつの問いにだけ答える：ゲームが先へ進む前に、プレイヤーが 必ず答えなければならないか？ そうなら塞ぐ。そうでないなら決して塞がない — 頼んでもいない知らせでゲームを止める カードは、プレイヤーにゲームを閉じさせるいちばんの近道だ。

  1. 答えのある問い — 購入、削除、退出、上書き → GoDialogs.confirm()。確認してもらうだけのこと → alert()。いくつかから1つ → choose()。
  2. それ自体が1つの画面 — 設定、キャラクターシート、ショップのアイテム → 画面中央の GoSurface。
  3. 長いリストや管理画面 — かばん、メール、フレンド → スマホでは下から出る GoSheet、広い画面では横から出る GoDrawer。
  4. 今押したものについての情報 — アイテムのステータス、できる操作 → その脇に出る GoPopover か GoContextMenu。
  5. ゲームを止めずに伝えられる知らせ — 保存した、捨てた、招待された → GoSnackbar、GoNotice、GoPromptCard。これらは画面を占領しない。
  6. 操作を教える → GoCoachMark。開発中のチート → GoConsole。

ポップアップの構造

gohud でゲームを塞ぐポップアップのほとんど — ダイアログ、シート、ポップオーバー、コンボボックスのリスト、 自作のウィンドウ — は1つのノード、GoSurface だ。その部品を一度覚えれば、全部が分かる。

部品何か触り方
レイヤーポップアップが載る CanvasLayer。その番号で何を覆うかが決まる。GoSurface では自分で決める。ほかは組み込み（表）
幕背後全体にかかる覆い。カードを外れたタップを受け止める。scrim_transparent、dismiss_on_scrim、テーマの scrim 色
カードウィンドウそのもの — テーマのパネルの面だ。見た目によって丸い、面取り、鍛造、ゼリーになる。card、alpha
ヘッダー任意の戻るボタン、タイトル（最大2行、あふれると「…」）、閉じるボタン。set_title() · set_title_key() · set_back() · close_enabled · show_header
ツールバーヘッダーの下に固定された行 — 検索欄、フィルターのチップ。使うまでは隠れている。toolbar
本文スクロールする部分。中身はここに入れる。body · scroll_body · clear()
ステータス行本文とフッターの間に固定された1行 — 「名前の確認に失敗」「保存中…」。set_status_text() · set_status_key() · clear_status()
フッター下に固定されたボタン。使うまでは隠れている。footer
固定したいものは固定の行に置く。 検索欄やエラーや保存ボタンを本文に入れると、長いリストと一緒にスクロールして 消える — プレイヤーが名前を打ち間違えても、エラーは画面の下に埋もれ、何も起きていないように見える。 toolbar、ステータス行、footer を使う。本文がスクロールしても、その場に留まる。

await で受け取るダイアログ

GoDialogs は尋ねて、待つ。ノード1つに問いが3種類 — 答えが同じ行に返ってくるので、 コードがプレイヤーの体験する順に読める。

var dialogs := GoDialogs.new()
add_child(dialogs)

if await dialogs.confirm("Buy the starter pack?", "300 gems for a sword, a shield and 10 potions.",
        "Buy", "Not now"):
    buy_starter_pack()

3種類の問い

confirm(title, body, ok_text := "", cancel_text := "", extra := "",
        args := {}, destructive := false) -> bool
alert(title, body, ok_text := "", extra := "", args := {})      # 待つなら await する
choose(title, options: Array, cancel_text := "", translate := false) -> int
confirm_key(…) · alert_key(…)                                 # 翻訳キー
呼び出し戻り値用途
confirm()true か falseはいかいいえ — 購入、削除、退出、上書き。
alert()なし — 待つなら await するプレイヤーが必ず見るべきこと：報酬、切れた接続。
choose()選んだ選択肢の番号、または -1いくつかから1つ。選択肢は String か {text, icon, danger, subtitle} だ。
confirm_key() · alert_key()同上翻訳キーを使う同じ呼び出し — ダイアログを開いたまま言語を変えても、文言が追従する。

ボタンの文言を空にすると、キット自身の言葉（GoConfig.text_keys の confirm、cancel）になる。 extra は本文の下に改行して足される。args はタイトルと本文の {placeholders} を 埋める：confirm("Buy {item}?", "It costs {price} gold.", "Buy", "", "", {"item": name, "price": 300})。

どう抜けても答えが返る

プレイヤーが…confirmalertchoose
OK / 選択肢を押すtrueawait が終わる選んだ選択肢の番号
キャンセルを押すfalse—-1
×、Escape、Android の戻るを押すfalseawait が終わる-1
幕をタップする（dismiss_on_scrim のときだけ）falseawait が終わる-1
GoDialogs ノードがツリーから外れるfalseawait が終わる-1

だから await の後のコードは必ず実行される — ダイアログの下でシーンが変わっても、答えが宙に浮いたまま残ることはない。

取り消せない操作

元に戻せないことには destructive = true を渡す。OK ボタンが塗りつぶしの Tone.DANGER_SOLID ボタンになる — どの見た目でも赤地に白文字だ。淡く色を付けた危険ラベルでは、ライトテーマで 読めるようにするためにほぼ黒まで暗くするしかない。ウィンドウは使い回されるので、トーンは呼ぶたびに設定し直される。

if await dialogs.confirm("Delete this save?", "Slot 2 — Aria, level 12. This cannot be undone.",
        "Delete", "Keep it", "", {}, true):
    delete_save(2)
キーボードフォーカスは OK にある。 どの確認も OK ボタンにフォーカスを置いて開くので、Enter や Space で確定する — 取り消せない確認でも同じだ。安全な選択が一目で分かる文言にし（「残す」）、うっかり一つでプレイヤーの進行が本当に 失われる操作は、もう一段階の手順の向こうに置く。

ボタンの並べ方

action_layoutすること
VERTICAL（既定）ボタンを全幅で縦に積む。どの言語でも安全だ — 長いドイツ語やロシア語のラベルでも窮屈にならない。
HORIZONTAL1行に半分ずつの幅で並べる。
AUTO両方のラベルがカードの半分の幅に1行で収まるときだけ横に並べ、収まらなければ積む。言語やサイズが変わるたびに決め直す。

action_gap はボタンどうしの間隔、body_gap はその上の間隔だ — ボタン間より広くとると、 問いと選択肢が2つの部分として読める。1つのダイアログにだけ効かせたいときは、開く前に set_next_action_layout() を呼ぶ。alert のボタン1つは常に全幅をとる。

一度に1つ

1つ開いている間に2つめの confirm() を呼ぶと、即座に false が返る — ダイアログがうっかり ダイアログの上に積み重なることはない。queue_when_busy を有効にすると、代わりに順番を待つ。alert() は常に待つ。 queue_limit（8）が待ち行列の長さを抑え、あふれると最も古い要求に false が返る。 pending() は待っている要求を数え、clear_pending() はそのすべてに false を返す。 choose() は並ばない：すでにダイアログが開いていれば -1 を返す。

スマホとデスクトップ

choose() は Android と iOS では親指の届く下からシートとして、デスクトップでは中央のカードとして 開く。確認は幅が max_width（420dp）で抑えられ、中央に置かれる。layer_index、 max_width などの export は add_child の前に設定する。ノードがツリーに入るときに適用されるからだ。

var picked := await dialogs.choose("Sort the bag by", [
    {"text": "Newest first", "icon": GoIconSet.CLOCK},
    {"text": "Rarity", "icon": GoIconSet.STAR},
    {"text": "Drop everything", "icon": GoIconSet.TRASH, "danger": true}])
if picked >= 0:
    sort_bag(picked)

GoSurface — 自作のウィンドウ

ポップアップが問い以上のもの — 設定、キャラクターシート、購入するアイテム — になるなら、 GoSurface の上に組む。セーフエリア、キーボード、固定の行、スクロール、戻る、フォーカス、サイズ変更はもう済んでいる。

var layer := CanvasLayer.new()
layer.layer = 50
add_child(layer)

var window := GoSurface.new()
window.set_title("Settings")
window.close_requested.connect(layer.queue_free)
window.body.add_child(GoStyle.toggle("Music", false))
window.body.add_child(GoStyle.slider(0.0, 1.0, 0.05))
var row := GoStyle.row()
row.add_child(GoStyle.button("Cancel", window.request_close))
row.add_child(GoStyle.button("Save", save_and_close, GoStyle.Tone.PRIMARY))
window.footer.add_child(row)
window.footer.visible = true
layer.add_child(window)
自分では閉じない。 ×、Escape、戻る、幕のタップは close_requested を出すだけだ。ウィンドウを隠すか 解放するかは、持ち主である画面の仕事だ — 「閉じる」が保存なのか、破棄なのか、先に確認するのかは、その画面にしか分からない。

3つの配置

ANCHOR には anchor_control が要る。カードは anchor_min_width が収まればその右に、 収まらなければ広いほうの側に、それも無理なら画面の内側に置かれ、上の余地のほうが大きければ上向きに開く。動くアンカーには 毎フレーム追従する。大きさは anchor_width（320）と anchor_max_height（520）で決まる。

どこまで大きくなるか

寸法規則変える方法
余地セーフエリアからキーボードと画面の余白（16dp、短辺の10%を超えない）を引いた範囲。—
幅縦向きでは余地の94%、横向きでは72%、最大480dp。max_width · GoConfig.surface_width_ratio_*
高さ中身の高さ（fit_content）で、余地の68%まで、上限は72%。サイズ変更できない中央のカードは、スクロールを避けるために94%まで伸びることがある。height_ratio · max_height_ratio · max_height
密度compact が設定されているか、画面の高さが420dp未満（横にしたスマホ）か、中身が収まらないと詰める：余白が減り、間隔が狭まり、タイトルが小さくなる。両方を測り、収まるうちでゆとりのあるほうを選ぶので、ちらつかない。compact
サイズ変更resizable ならタイトルがハンドルになる：30%から上限までドラッグで変えられる。結果は height_changed(ratio) が知らせる。resizable

上限を超える比率は切り詰められ、デバッグビルドで一度だけ警告が出る。キーボードはカードを押し上げ、フォーカスのある 入力欄が見えるようにスクロールする。セーフエリアのおかげで、Android と iOS でもノッチやジェスチャーバーにかからない。

プロパティ

プロパティ既定値すること
placementCENTERCENTER、BOTTOM、ANCHOR のいずれか
dismiss_on_scrimGoConfig.dismiss_on_scrim（false）幕をタップすると閉じるよう求める。カードの中で始まったドラッグは数えない。
scrim_transparentfalseゲームを見せたままにする — それでも幕は外側のタップを受け止める。

シートとドロワー

場所の要るリストは、縦に持ったスマホでは親指のある下からせり上がり、タブレットやデスクトップでは 横から入ってくる — そこではシートがゲームを覆ってしまうからだ。

GoSheet — 下から出るページ

var sheet := GoSheet.new()
add_child(sheet)

func show_bag(items: Array) -> void:
    sheet.open("Bag")
    var search := GoStyle.line_edit("Search the bag…")
    search.text_changed.connect(filter_bag)
    sheet.toolbar().add_child(search)
    sheet.toolbar().visible = true
    for item in items:
        sheet.body.add_child(GoStyle.list_button(GoIconSet.BOX, item.name, show_item.bind(item),
            Color.TRANSPARENT, item.description, false, GoIconSet.CHEVRON_RIGHT))
    sheet.add_footer(GoStyle.button("Close", sheet.close, GoStyle.Tone.PRIMARY))
  • BOTTOM 配置でサイズ変更できる GoSurface を持つ CanvasLayer（レイヤー10）だ — だから HUD より上に出て、プレイヤーはドラッグで高くできる。
  • open(title) は新しいページを始める：本文、ツールバー、戻るボタンをクリアし、add_footer() で足したものを 解放する。同じシートで別のページを見せるには、もう一度呼ぶ。set_back() は最初のページへ戻るための戻るボタンを 表示する。open_key() は翻訳キーを受け取る。
  • close() は隠す — 解放はしないので、次の open() は即座に開く。いつ起きたかは closed と page_changed が知らせる。
  • height_ratio（0.6）は開くときの高さ、max_height_ratio は上限を引き上げる。dismissable （true）なら幕のタップで閉じる。
Escape と戻るはシート全体を閉じる。set_back() のあるサブページでもそうだ — 1ページ戻るのは画面上の 戻るボタンだけだ。戻るで1段ずつ戻したいなら、sheet.surface の close_requested を自分で処理する。

GoDrawer — 横から

var drawer := GoDrawer.new()
drawer.side = GoDrawer.Side.LEFT
drawer.follow_text_direction = true      # 始まりの側：左、アラビア語では右
add_child(drawer)
drawer.body.add_child(GoNavBar.drawer_list([{"icon": GoIconSet.HOME, "text": "Town"},
    {"icon": GoIconSet.MAP, "text": "World map"}], 0, go_to))
drawer.open("Menu")
  • レイヤー80。幅は画面の42%（width_ratio）で、min_width（320dp）と max_width （420dp）の間だ — スマホでは画面の大半を覆うので、そこではシートのほうがよい。
  • パネルは画面の端まで届き、中身だけがセーフエリアの内側に入る。だから丸めた角が最初の行を切り落とさない。
  • LEFT はアラビア語でも画面の左だ。「始まりの側」であることが要点なら follow_text_direction を 有効にする。実際にどちらに出たかは effective_side() が教えてくれる。
  • open(title) は本文をそのまま残す — 一度だけ埋める。set_title("") はヘッダーを隠す。 motion_seconds（0.2）で滑り込み、reduce_motion なら即座に出る。
Android の戻るはドロワーを閉じるが、Escape は閉じない。 ドロワーが聞くのはシステムの戻るだけだ。デスクトップでは 自分のキー割り当てから drawer.close() を呼ぶ — また、GoSurface.is_any_open() はドロワーを数えない ことに注意する。drawer.is_open() に尋ねる。

コントロールの脇に出るカードとメニュー

プレイヤーが今押したものには、画面の真ん中ではなく指のすぐ横で答えるべきだ。

GoPopover — 押したものに付くカード

slot.pressed.connect(func() -> void:
    var card := GoStyle.item_card({"icon": GoIconSet.POTION, "title": "Health potion",
        "subtitle": "Heals 50 HP · 12 left"}, false)
    GoPopover.open(slot, card, {"width": 280}))

レイヤー、アンカー、後片付けまで配線済みの ANCHOR サーフェスだ — どのゲームも何度も書く、あの10行である。 一度に1つ：2つめを開くと1つめが閉じる。カードが積み重なると画面が埋まり、どのカードがどのスロットのものか 誰にも分からなくなるからだ。幕は透明だ — 装備を見比べるために開いたカードが、その装備を暗くしてはならない — が、外側の最初のタップは受け止める。そのタップはカードを閉じるだけで、先へは届かない。

オプション既定値すること
title""× 付きのヘッダー。空ならヘッダーなし。
width · max_height320 · 520カードの大きさ。
dismissabletrue外側のタップで閉じる。
compact · alpha · translatefalse · -1 · false詰めた間隔、面の不透明度、タイトルを翻訳キーとして扱う。
layer95開く先の CanvasLayer。

GoPopover.close() と GoPopover.is_open() は static だ。open() はサーフェスを返す — アンカーがツリーにないときは null なので、await shown.close_requested の前に確かめる。

ホバーのツールチップではない。 タッチにホバーはない。マウスでしか現れないものは、プレイヤーの半分には見えない。 そして dismissable = false でタイトルもなければ、画面上にそれを閉じるものは何もない — Escape、戻る、自分で呼ぶ処理だけだ。

GoContextMenu — 長押しと右クリック

var menu := [
    {"text": "Use", "icon": GoIconSet.POTION, "action": use},
    {"separator": true},
    {"text": "Drop", "icon": GoIconSet.TRASH, "action": drop, "danger": true}]
GoContextMenu.attach(slot, menu)

var more := GoStyle.icon_button(GoIconSet.MORE, Callable(), -1, &"more")
more.pressed.connect(func() -> void: GoContextMenu.open_at(more, menu))
  • 右クリックはすぐに開く。指を0.5秒（HOLD_SECONDS）置くと開き、12dp を超えて動くと 取り消す — だからリストをスクロールしてもメニューは出てこない。
  • 項目は {text, action, icon, disabled, checked, separator, danger, translate} だ。押したものによって項目が変わるなら、 配列の代わりに Callable を渡す。メニューが開くたびに呼ばれる。
  • danger は文言の前に「⚠ 」を付ける — エンジンのメニューは全項目の色をまとめてしか変えられないからだ。
  • エンジンの PopupMenu を GoStyle.style_popup() で装ったものだ。開いているサーフェスとしては数えない。
長押しには、もう1つの入り口が要る。 隠れたジェスチャーは誰にも見つけられない。目に見える ⋯ ボタン （上のように open_at()）と組み合わせるか、コーチマークで一度教える。

レイヤー、戻る、入力

何かが開いている間にプレイヤーが何に触れられるかは、3つの規則で決まる：何が上にあるか、 戻るは誰のものか、タップは誰が受けるか。

何が上にあるか

この順には理由がある：スナックバーは今起きたことを知らせるので、ドロワーの上で読める。ポップオーバーは今押したものに 属するので、その上に乗る。ダイアログは問いを投げるので両方を覆う。コンソールはすべてを覆う — ほかが全部おかしくなった ときに開くものだからだ。

戻るは誰のものか

  • 答えるのは最前面のウィンドウだけだ。 開いているサーフェスのうち、いちばん高いレイヤーのもの（同じならツリーで最も後のもの）が、 Escape、ゲームパッドのキャンセル（ui_cancel）、Android の戻る、幕のタップを受け取る。重ねたウィンドウは1枚ずつ閉じ、 まとめては閉じない。
  • Android の戻るは1フレーム遅れて処理されるので、1回押してウィンドウが2枚閉じることはない。
  • 戻るを持つものが開いている間、Android の戻るはアプリを終了しない（GoBackPolicy が持ち主を数え、 最後の1つが閉じると quit_on_go_back を元に戻す）。戻るを受け取る自作のポップアップは GoBackPolicy.acquire() と release() を呼ぶ — _exit_tree でも。
  • ドロワー、コーチマークのツアー、フォームは、サーフェスが開いている間は身を引く — 戻るはまずサーフェスに届く。
  • GoConfig.close_on_back（有効）がサーフェスのスイッチだ。

タップは誰が受けるか

  • サーフェスは画面全体を覆って入力を止める — 透明な幕でもそうだ。開いている間、下のレイヤーにあるものは 何も押せない。上のレイヤー（スナックバー）は押せる。
  • マウスホイールやピンチのジェスチャーもウィンドウで止まる：リストの端を越えてスクロールしても、ゲームはスクロールしない。
  • コントロールを通らないゲームの入力 — 移動用の _unhandled_input、カメラのドラッグ — は止めるべきだ： if GoSurface.is_any_open(): return。これでダイアログ、シート、ポップオーバー、コンボボックスが含まれる。ドロワーには 別に is_open() を尋ねる。
  • スナックバー、通知、プロンプトカード、コーチマークは自分のカードでだけ入力を受ける。それ以外の場所では、ゲームが受け取る。

フォーカス

ポインターで開いたウィンドウは何にもフォーカスを与えない — タッチでフォーカスリングが光ることはない。キーボードやゲームパッドで 開くと、閉じるボタン（または initial_focus）がフォーカスを受ける。開いている間フォーカスはウィンドウの中に留まり、 閉じると、それまでフォーカスを持っていたコントロールへ戻る。ダイアログは毎回 OK にフォーカスを置く。

ゲームの一時停止

ツリーを一時停止するとポップアップも止まる — 動き続けるのはコンソールだけだ。ポーズメニューなら、そのレイヤーに process_mode = PROCESS_MODE_ALWAYS を与える。すると、ゲームが止まっている間もウィンドウ、ボタン、戻るが動き続ける。

func _unhandled_input(event: InputEvent) -> void:
    if GoSurface.is_any_open() or drawer.is_open():

    handle_gameplay(event)

落とし穴

  • GoSurface は自分では解放されない。 close_requested をつながないと、× を押しても何も起きない。
  • add_child の後に設定したオプション — scrim_transparent、show_header、resizable、 scroll_body、そして GoDialogs の layer_index と max_width — は適用されない。
  • 2つめの confirm() は即座に false を返す。 2つの問いが重なりうるなら queue_when_busy を有効にする。
  • Enter で確定する。 取り消せないダイアログでも OK にフォーカスがある。
  • シートで戻るを押すと、シートが閉じる。 サブページが閉じるのではない。
  • Escape はドロワーを閉じず、 is_any_open() もドロワーを見ない。
  • ポップオーバーやコンボボックスのリストは、閉じるまでゲームを塞ぐ。 幕が透明でもそうだ — しかも dismissable = false でタイトルのないポップオーバーには、画面上に閉じる手段がない。
  • プロンプトカードは隠れた状態で始まり、 時間切れもない。
  • seconds: 0 でボタンのないスナックバーは、いつまでも消えない。 しかも既定では自分のカードへのタップを受け取る。
  • 誰も知らない長押しは、誰も使わない機能だ。 ⋯ も表示する。
  • 一時停止したツリーはポップアップも止める。 そのレイヤーに PROCESS_MODE_ALWAYS を使う。
  • 幅のない通知は いちばん狭く縮む — preferred_width() を使う。
  • スナックバーで尋ねず、ダイアログで知らせない。 無視された問いは消えてしまうし、知らせのためにゲームを止めるべきではない。
