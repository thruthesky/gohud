テーマ設定

gohud の見た目は3つの層でできている。色だけを変えることも、形ごと入れ替えることもできる。

3つの層

プリセットは3つをまとめて束ねたものだ。空のままにした項目はデフォルトに落ちる。

層決めるもの変え方
Theme 色、サイズ、文字の大きさ、そしてエンジンが描くものすべての形 — ボタンのパネル、入力欄、タブ、トグルの絵 .tres を書くか、tools/make_theme.py で生成する
GoSkin コードが描くものすべての形 — スティック、クイックスロットの面、コーチマークのリング、チップ、スケルトン、区切り線、セクション見出し 継承して、気にするメソッドだけを上書きする
GoIconSet 名前で引くアイコン — デフォルトの84枚、あるいはその上に重ねる中世セットの彫刻風16枚。テクスチャパックでもアイコンフォントでもよく、呼び出すコードはどちらでも同じだ セットを丸ごと渡すか、いくつかの名前だけ差し替える
Theme だけでは足りない理由。 StyleBoxFlat が持つ角は丸だけだ — 半径を 0 にすれば直角になるが、その中間は存在しない。斜めに切り落とした角、1辺だけ太い縁、外へにじむ発光。 エンジンはそのどれも描かない。しかもスティックとコーチマークは _draw() の中で描かれており、 テーマはそこへ届かない。

選ぶ

GoUi.use_preset(GoThemePresets.SCIFI_DARK)

この1行でテーマ・スキン・アイコンが入れ替わる。エディタからは プロジェクト設定 → Gohud → Theme → Preset、設定リソースからは GoConfig.preset で指定する。

1つだけ自分のものを使う

GoUi.use_preset(GoThemePresets.SCIFI_DARK)
GoUi.config.icons = my_icons     # アイコンだけ自前、ほかはプリセットのまま

theme・skin・icons を明示的に設定すると、プリセットより優先される。

プリセットパネルスキン · アイコン
default_dark · default_light段階的な影を持つ丸い StyleBoxFlat のパネル。主ボタンは押すと沈み、離すと持ち上がるGoSkin · デフォルトアイコン84種

中世 — 鉄、革、そして羊皮紙

medieval_dark は暗い鉄と革にアンティークゴールドを合わせる。medieval_light は羊皮紙とインクを使う。どちらも GoSkinMedieval と既存のウィジェット、そして彫刻の描き込みを入れた オリジナルアイコン16種を使う。ナビゲーション用のアイコンは元のセットに落ちる。

GoUi.use_preset(GoThemePresets.MEDIEVAL_DARK)
# または: GoUi.use_preset(GoThemePresets.MEDIEVAL_LIGHT)

プリセットは UI を作る前に選ぶ。GoConfig.theme・skin・icons を 明示的に指定した場合は、そちらが優先されたままだ。 res://addons/gohud/examples/medieval/medieval.tscn を開いて F6 を押せば、動くキャラクターシート・ 雑嚢・クエストジャーナルが見られる。ボタンでバリアントを切り替え、アイテムの詳細を開ける。

メニューの枠にはリベットと小さな角飾りがあり、常に見えている HUD は縁を静かに保つ。 体力・マナ・スタミナは赤・青・オリーブで塗る。Cinzel はタイトルとサブタイトルに限って使い、 本文はホスト側またはデフォルトのフォントのままだ。同梱フォントのライセンスは assets/fonts/cinzel/OFL.txt にある。

彫刻セットが描き直すのは bag、book、box、coin、crown、 flag、heart、key、map、potion、shield、 star、sword、user で、さらに scroll と seal を足す。 それ以外の名前はデフォルトセットに落ちるので、close や settings はどのプリセットでも 同じ絵のままだ。Cinzel が持つのはラテン文字なので、各言語の見出しには shape.fonts から 専用のフォントを与える。

テストスイートが両バリアントで確かめること。 中世スキンが選ばれていること。メニューと HUD のパネルが 鍛造の枠で、角飾りはメニューにだけ付くこと。タイトルが Cinzel を使い、本文は継承したフォントを保つこと。 彫刻アイコンが DPITexture としてインポートされること。実物のクイックスロットがスキンを使うこと。 複製したスキンのダイヤルを変えると、プリセットに触れずにスロットへ届くこと。そして戻したときに、 デフォルトと SF のジオメトリが復元されること。

StyleBoxFlat では作れない形

クラス描くもの
GoStyleBoxCut斜めに切り落とした角、1辺だけ太いアクセント縁、外へにじむ発光

3つともほかの StyleBox と同じように Theme リソースへ保存される — だからテーマが形まで変えられる。

余白は content_margin_* で与える。 GDScript で StyleBox を継承すると _get_style_margin() は呼ばれない（Godot 4.7 で実測）。組み込みのフィールドを埋めないと、 中身が枠に貼り付いてしまう。

自分のプリセットを、ファイル1枚で

テーマを1つ足すのに、かつては4か所を手で編集する必要があった — ビルダーのパレット、形、スキン、 プリセットのリソース。いまは1つのコマンドがすべてを置いてくれる。 

python3 addons/gohud/tools/new_theme.py neon --from scifi_dark --title "Neon"
python3 addons/gohud/tools/make_theme.py neon      # テーマの .tres + コントロールの絵
godot --headless --path . --import                  # 新しい絵を一度だけインポートする
GoUi.use_preset(&"neon")                             # 完了 — 選択リストにも出てくる

最初の行が themes/palettes/neon.json と themes/presets/neon.tres を書く。 この JSON には継承元テーマのすべての値が省略なしで書き出されるので、そのまま「変えられるものの一覧」 にもなる。キーを消せば親の値のまま、書けば上書きだ。プリセットは themes/presets/ を 走査して見つけるので、登録コードの変更はいらない — プロジェクト設定のドロップダウンにも同じように載る。

スキンを継承する（任意）

スキンにあるのは、テーマと形では届かないものだけだ — スティックの六角形、スロットのバッジ、 コーチマークの照準ブラケット。GoSkin を継承してそれらのメソッドだけを上書きし、JSON の skin をそのリソースへ向ける。色だけのテーマなら、この手順はいらない。

約束を守らせるのは検査だ。 tools/check_scaffold.sh は実行のたびに使い捨てのテーマを作り — アクセントを変え、半径を 4 にして — 生成・トークンの伝播・コントラスト検査の通過までを確かめてから消す。 最初の実行では、アクセントだけを変えたテーマが8組で不足していた。ビルダーが文字色は押し上げるのに、 アクセントは書かれたまま使っていたのだ。いまはアクセントと、その上のラベルも押し上げる。

読みやすさは測って決める

「きれい」は好みだが、「読める」は測れる。 薄い灰色の文字は良いモニタでは平気に見えて、 日中の屋外ではスマートフォンから消える — 目で選んでいれば、いつか必ずそうなる。 

python3 addons/gohud/tools/check_contrast.py
対象必要な比
本文の文字4.5 : 1
大きな文字(24px 以上)3 : 1
アクセントの枠とアイコン3 : 1
装飾の枠2 : 1 — WCAG は装飾に 3:1 の規則を課していない
隣り合う面1.12 : 1 — カードが背景と別物だと分かる程度

同系色の文字を同系色の淡い面に載せる

この落とし穴は、このコードベースで3度現れた — 押されたボタン（アクセントのパネルにアクセントの文字）、 危険ボタン、そしてチップだ。色見本の上ではよく見えるのに、測った瞬間に崩れる。 2つが同じ色相を共有していて、明度の差がないからだ。

だからラベルの色は手で選ばない。テーマのビルダーと GoSkin はそれぞれ、文字が実際に載る パネルの上でしきい値を超えるまで明度だけを押し上げる。色相と彩度は残るので、パレットは持ち味を保ち、 変更してもコントラストは保たれる。

文字として読む色と、面として塗る色は求めるものが逆だ

ライトテーマでは、警告色は文字として読めるよう暗くしなければならない(#96500A)。 バーの塗りがそれを受け継ぐと、経験値バーは茶色になる。色だけでは直せない。黄色はそもそも明るく、 灰色の溝に対して 3:1 をまったく満たさないし、溝を暗くするともっと悪くなる(1.52 → 1.06)。

そこで両者を切り離した。色は鮮やかなまま — パレットは warning_vivid のような 塗り専用の色を持つ。コントラストは縁が担う — GoSkin は、溝に対して 3:1 に届かない塗りに 1dp の輪郭を描く。こうして「どれだけ溜まっているか」は読めるままになる。 

MY_LIGHT = dict(
    warning=hexc("9A5407"),         # 文字として読む色
    warning_vivid=hexc("F2A007"),   # バーに塗る色
)
書き忘れは報告される。 *_vivid がないまま塗りが暗くなると、ビルダーは 막대가 칙칙하다 — 팔레트에 warning_vivid 를 더한다 と出力する（ビルダーが実際に出す文言）。 黙って劣化していた場所が、いまは声を上げる。

浮かぶパネルは、背後に何があるか知りようがない

HUD はゲームの上に描かれる — 雪原かもしれないし、洞窟かもしれない。パネルが半透明なら背後のものが 透けてパネルの色そのものを変え、文字のコントラストまで道連れにする。不透明度 82% では、明るい背景の上で ダークテーマの控えめな文字が 3.74:1 まで落ちた — 最低基準を下回っている。

そこで半透明のパネルは純白と純黒を背後に置いて測る。ゲームの場面が出しうる最悪がその2つだからだ。 同梱テーマの HUD パネルは、ガラスのような見え方を保ったまま基準を通る不透明度 (92%) にしてある。

同じ理由でアイコンの色も固定していない。クイックスロットのグリフは白で決め打ちされていて、 ライトテーマで 1.11:1 と測れた — いまはラベルとまったく同じように、載っているパネルに従う。

2つの検査、2つの守備範囲。 check_contrast.py はテーマファイルを読む。 スキンが実行中に混ぜる色（チップ、スロット）は、Godot の中で走るテストスイートの skin contrast の節が測る。
