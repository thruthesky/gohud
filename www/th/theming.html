ธีม

หน้าตาของ gohud มี สามชั้น จะเปลี่ยนแค่สี หรือจะเปลี่ยนรูปทรงทั้งหมดก็ได้

สามชั้น

พรีเซ็ตหนึ่งอันรวมทั้งสามชั้นไว้ด้วยกัน ช่องที่ปล่อยว่างจะย้อนกลับไปใช้ค่าเริ่มต้น

ชั้นกำหนดอะไรเปลี่ยนอย่างไร
Theme สี ขนาด สเกลตัวอักษร และรูปทรงของทุกอย่างที่เอนจินเป็นคนวาด — พาเนลของปุ่ม ช่องกรอก แท็บ ภาพของสวิตช์ เขียนไฟล์ .tres เอง หรือให้ tools/make_theme.py สร้างให้
GoSkin รูปทรงของทุกอย่างที่โค้ดเป็นคนวาด — จอยสติ๊ก หน้าควิกสล็อต วงแหวนโค้ชมาร์ก ชิป สเกเลตัน เส้นคั่น หัวข้อส่วน สืบทอดคลาสแล้วเขียนทับเฉพาะเมธอดที่สนใจ
GoIconSet ไอคอนที่เรียกด้วยชื่อ — ภาพค่าเริ่มต้น 84 ชิ้น หรือภาพสลัก 16 ชิ้นของชุดยุคกลางที่ทับลงไป จะเป็นเท็กซ์เจอร์แพ็กหรือไอคอนฟอนต์ก็ได้ โค้ดที่เรียกใช้เหมือนกันทั้งสองทาง ใส่ชุดไอคอนเข้าไป หรือเขียนทับเฉพาะบางชื่อ
ทำไม Theme อย่างเดียวถึงไม่พอ มุมมนคือมุมชนิดเดียวที่ StyleBoxFlat มี — ตั้งรัศมีเป็นศูนย์แล้วได้มุมฉาก ไม่มีอะไรอยู่ระหว่างนั้นเลย ส่วนมุมตัดเฉียง ขอบหนาด้านเดียว และแสงเรืองรอบนอกนั้น เอนจินไม่วาดให้สักอย่าง ยิ่งกว่านั้น จอยสติ๊กกับโค้ชมาร์กถูกวาดใน _draw() ซึ่งเป็นที่ที่ธีมเอื้อมไม่ถึงเลย

เลือกพรีเซ็ต

GoUi.use_preset(GoThemePresets.SCIFI_DARK)

บรรทัดเดียวนั้นสลับทั้งธีม สกิน และไอคอน ถ้าทำจากเอดิเตอร์ ให้ไปที่ Project Settings → Gohud → Theme → Preset ถ้าทำจากรีซอร์สตั้งค่า ให้ใช้ GoConfig.preset

เก็บบางช่องไว้เป็นของตัวเอง

GoUi.use_preset(GoThemePresets.SCIFI_DARK)
GoUi.config.icons = my_icons     # ไอคอนของคุณ ที่เหลือใช้ของพรีเซ็ต

การกำหนด theme, skin หรือ icons ไว้ตรง ๆ จะชนะพรีเซ็ต

พรีเซ็ตที่มีมาให้ทั้ง 6 แบบ

พรีเซ็ตพาเนลสกิน · ไอคอน
default_dark · default_lightพาเนล StyleBoxFlat มุมมน บนสเกลเงาที่ไล่ระดับ ปุ่มหลักยกตัวขึ้นและยุบลงเมื่อถูกกดGoSkin · ไอคอนค่าเริ่มต้น 84 ชิ้น
scifi_dark · scifi_lightพาเนล GoStyleBoxCut มุมตัดเฉียง พร้อมขอบนีออนและแสงเรือง เครื่องหมายโฟกัสแบบ GoStyleBoxBracketGoSkinSciFi — จอยสติ๊กหกเหลี่ยม · ไอคอนค่าเริ่มต้น
medieval_dark · medieval_lightกรอบตีขึ้นรูป GoStyleBoxMedieval — เหล็กและหนัง หรือกระดาษหนัง พร้อมหมุดย้ำและลวดลายมุมบนเมนูGoSkinMedieval · ไอคอนสลัก 16 ชิ้นทับบนชุดค่าเริ่มต้น

ยุคกลาง: เหล็ก หนัง และกระดาษหนัง

medieval_dark จับคู่เหล็กดำและหนังเข้ากับทองโบราณ ส่วน medieval_light ใช้กระดาษหนังและหมึก ทั้งคู่ใช้ GoSkinMedieval วิดเจ็ตชุดเดิม และไอคอนออริจินัล 16 ชิ้น ที่มีรายละเอียดลายสลัก ส่วนไอคอนนำทางย้อนกลับไปใช้ชุดเดิม

GoUi.use_preset(GoThemePresets.MEDIEVAL_DARK)
# หรือ: GoUi.use_preset(GoThemePresets.MEDIEVAL_LIGHT)

เลือกพรีเซ็ตก่อนสร้าง UI ทั้งนี้ค่า GoConfig.theme, skin หรือ icons ที่กำหนดไว้ตรง ๆ ยังคงมีอำนาจเหนือกว่าอยู่ดี เปิด res://addons/gohud/examples/medieval/medieval.tscn แล้วกด F6 เพื่อดูแผ่นข้อมูลตัวละคร ย่าม และสมุดบันทึกเควสต์ที่ใช้งานได้จริง ปุ่มในนั้นสลับตัวแปรของธีมและเปิดรายละเอียดไอเทมได้

กรอบเมนูมีหมุดย้ำและลวดลายมุมเล็ก ๆ ส่วน HUD ที่มองเห็นตลอดเวลายังคงมีขอบเรียบสงบ พลังชีวิต มานา และสตามินา ใช้สีแดง น้ำเงิน และเขียวมะกอกเป็นสีเติม Cinzel ถูกจำกัดไว้ที่หัวข้อและหัวข้อรอง ส่วนเนื้อความยังใช้ฟอนต์ของโปรเจกต์แม่หรือฟอนต์ค่าเริ่มต้น ฟอนต์ที่แถมมามีสัญญาอนุญาตอยู่ที่ assets/fonts/cinzel/OFL.txt

ชุดไอคอนสลักวาดใหม่ให้กับ bag, book, box, coin, crown, flag, heart, key, map, potion, shield, star, sword และ user แล้วเพิ่ม scroll กับ seal เข้ามา ชื่ออื่นทั้งหมดย้อนกลับไปใช้ชุดค่าเริ่มต้น close และ settings จึงคงภาพเดิมไว้ในทุกพรีเซ็ต Cinzel รองรับเฉพาะอักษรละติน ถ้าต้องการหัวข้อในภาษาอื่นให้กำหนดฟอนต์ของมันเองผ่าน shape.fonts

ชุดทดสอบตรวจอะไรบ้างในทั้งสองตัวแปร ตรวจว่าสกินยุคกลางถูกเลือกจริง พาเนลของเมนูและ HUD เป็น กรอบตีขึ้นรูปโดยมีลวดลายเฉพาะบนเมนู หัวข้อใช้ Cinzel ขณะที่เนื้อความยังใช้ฟอนต์ที่สืบทอดมา ไอคอนสลัก ถูกอิมพอร์ตเป็น DPITexture ควิกสล็อตจริงใช้สกินนั้น การแก้ค่าปรับของสกินที่คัดลอกมาส่งผลถึง ตัวสล็อตโดยไม่ต้องแตะพรีเซ็ต และการสลับกลับไปคืนรูปทรงของชุดค่าเริ่มต้นกับชุดไซไฟได้ครบ

สร้างอาณาจักรของคุณเอง

python3 addons/gohud/tools/new_theme.py kingdom --from medieval_dark
# แก้ไข themes/palettes/kingdom.json แล้วสั่ง:
python3 addons/gohud/tools/make_theme.py kingdom
godot --headless --path . --import
# ใน GDScript ก่อนสร้างวิดเจ็ต:
GoUi.use_preset(&"kingdom")

ธีมแบบ JSON สืบทอดจากธีม JSON อื่นได้ ค่าที่ละไว้จะคงการตั้งค่าของธีมแม่ไว้ ส่วนการสืบทอดที่วนเป็นวงจะถูกปฏิเสธ พรีเซ็ตที่สร้างขึ้นจะใช้ชุดไอคอนของธีมแม่ต่อไป

การตั้งค่าผลที่ได้
shape.material0: เหล็ก · 1: หนัง · 2: กระดาษหนัง ควบคุมร่องรอยบนพื้นผิว
shape.grain_alphaความทึบของลายเนื้อวัสดุ ใส่ 0 เพื่อให้พื้นผิวเกลี้ยง
shape.ornament_scale · shape.bevel_strengthขนาดลวดลายมุมของเมนู และความเข้มของแสงไฮไลต์ตามขอบลาด
shape.fontsจับคู่บทบาท title, subtitle, caption, body และ button เข้ากับไฟล์ฟอนต์ res:// ที่อยู่ในแอดออน บทบาทที่ละไว้จะคงฟอนต์ที่สืบทอดมา
skin.dialsรัศมีของควิกสล็อต การแสดงหมุดย้ำ ลายเนื้อ และไฮไลต์ ตารางเต็มด้านล่างแจกแจงทุกค่าปรับ

โทเคน

ทุกสีและทุกค่าขนาดอยู่ใต้ชนิด GoHud ใน Theme และถูกอ้างถึงด้วยชื่อ กฎคือห้ามเขียนตัวเลข: ชื่อจะตามไปเองเมื่อมีการสลับธีม 

GoUi.color(GoTheme.ACCENT)             # สี
GoUi.metric(GoTheme.GAP)               # ค่าขนาด (dp)
GoUi.font_size(GoTheme.ROLE_CAPTION)   # ขนาดของบทบาทตัวอักษรหนึ่ง ๆ
GoUi.box(GoTheme.BOX_CARD)             # สำเนาของ StyleBox หนึ่งชิ้น

ทำไมต้องมี *_fill ความหมายเดียวกัน แต่ความต้องการตรงข้ามกัน warning เมื่อใช้เป็นตัวอักษรต้องเข้มพอจะอ่านออกบนพื้นสว่าง แต่เมื่อใช้เป็นสีเติมของแถบค่าประสบการณ์ มันต้องสว่างพอจะสะดุดตา โทเคนเดียวเป็นทั้งสองอย่างไม่ได้ — ที่ผ่านมาแถบของธีมสว่างเลยกลายเป็นสีน้ำตาล ธีมที่ไม่มีตัวแปร _fill จะย้อนกลับไปใช้ชื่อฐานโดยอัตโนมัติ ธีมเก่าที่มีมาก่อนโทเคนพวกนี้จึงยังใช้ได้

คลาสวาดอะไร
GoStyleBoxCutมุมตัดเฉียง ขอบเน้นสีที่หนาขึ้นหนึ่งด้าน และแสงเรืองรอบนอก
GoStyleBoxBracketเครื่องหมายมุมอย่างเดียว โดยไม่ล้อมกรอบเนื้อหา
GoStyleBoxMedievalกรอบตีขึ้นรูป — หมุดย้ำ ลายสลักที่มุม แสงไฮไลต์ตามขอบลาด และลายเนื้อเหล็ก หนัง หรือกระดาษหนัง

ทั้งสามคลาสซีเรียลไลซ์ลงในรีซอร์ส Theme ได้เหมือน StyleBox ตัวอื่น — นี่เองคือสิ่งที่ทำให้ธีมเปลี่ยนรูปทรงได้

ใส่ระยะขอบในผ่าน content_margin_* การสืบทอด StyleBox ใน GDScript หมายความว่า _get_style_margin() จะไม่ถูกเรียกเลย (วัดผลบน Godot 4.7) ให้กรอกช่องที่มีมาให้ ไม่อย่างนั้น เนื้อหาจะไปแปะติดเส้นขอบ

พรีเซ็ตของคุณเอง — ไฟล์เดียวจบ

เมื่อก่อนการเพิ่มธีมหนึ่งธีมหมายถึงต้องแก้ด้วยมือถึงสี่ที่ — จานสีของตัวสร้าง รูปทรง สกิน และรีซอร์สพรีเซ็ต ตอนนี้คำสั่งเดียวจัดการให้ครบทุกที่ 

python3 addons/gohud/tools/new_theme.py neon --from scifi_dark --title "Neon"
python3 addons/gohud/tools/make_theme.py neon      # ไฟล์ธีม .tres + ภาพของคอนโทรล
godot --headless --path . --import                  # อิมพอร์ตภาพใหม่หนึ่งครั้ง
GoUi.use_preset(&"neon")                             # เสร็จแล้ว — และมันโผล่ในตัวเลือกด้วย

บรรทัดแรกเขียนไฟล์ themes/palettes/neon.json และ themes/presets/neon.tres ตัว JSON บรรจุทุกค่าของธีมที่มันสืบทอดมาไว้อย่างละเอียดครบถ้วน มันจึงทำหน้าที่เป็นรายการของ สิ่งที่คุณเปลี่ยนได้ไปในตัว: ลบคีย์ทิ้งเพื่อคงค่าของธีมแม่ หรือเขียนคีย์ลงไปเพื่อเขียนทับ พรีเซ็ตถูกค้นหา ด้วยการสแกนโฟลเดอร์ themes/presets/ จึงไม่ต้องแก้โค้ดทะเบียนใด ๆ — และดรอปดาวน์ ในการตั้งค่าโปรเจกต์ก็มองเห็นมันเช่นกัน

อะไรเปลี่ยนได้บ้าง — รวมไว้ในหน้าเดียว

สืบทอดสกิน (ไม่บังคับ)

สิ่งที่ธีมและรูปทรงเอื้อมไม่ถึงเท่านั้น — หกเหลี่ยมของจอยสติ๊ก แบดจ์บนสล็อต วงเล็บเล็งเป้าของ โค้ชมาร์ก — ที่อยู่ในสกิน สืบทอด GoSkin เขียนทับเฉพาะเมธอดเหล่านั้น แล้วชี้ช่อง skin ใน JSON ไปที่รีซอร์สนั้น ธีมที่เปลี่ยนแค่สีข้ามขั้นตอนนี้ไปได้เลย

มีการตรวจสอบคอยรักษาคำมั่นนี้ไว้ tools/check_scaffold.sh สร้างธีมใช้แล้วทิ้ง ขึ้นมาทุกครั้งที่รัน — เปลี่ยนสีเน้น ตั้งรัศมีเป็น 4 — แล้วตรวจการสร้าง การกระจายของโทเคน และการวัด คอนทราสต์ให้ผ่านหมดก่อนจะลบมันทิ้ง การรันครั้งแรกพบว่าธีมที่เปลี่ยนแค่สีเน้นอย่างเดียวตกไปถึง 8 คู่สี: ตัวสร้างดันสีตัวอักษรให้ แต่ใช้สีเน้นตามที่เขียนมาดื้อ ๆ ตอนนี้มันดันทั้งสีเน้นและ ป้ายข้อความที่อยู่บนมันด้วย

ความอ่านง่ายเป็นเรื่องที่วัดได้

"สวย" เป็นเรื่องรสนิยม แต่ "อ่านออก" วัดได้ ตัวอักษรสีเทาจาง ๆ ดูดีบนจอมอนิเตอร์ดี ๆ แล้วหายไปเลยบนมือถือกลางแดด — เลือกด้วยตาเปล่าเมื่อไร ก็รับประกันว่าเจอปัญหานี้เข้าสักวัน

ตัวอักษรสีเดียวกันบนพื้นย้อมสีเดียวกัน

กับดักนี้โผล่มาแล้ว สามครั้ง ในโค้ดเบสนี้ — ปุ่มขณะถูกกด (พาเนลสีเน้น ป้ายข้อความสีเน้น) ปุ่มอันตราย และชิป มันดูดีเวลาอยู่บนแผ่นตัวอย่างสี แล้วพังทันทีที่ถูกวัด เพราะทั้งสองใช้เฉดสีเดียวกัน จึงไม่มีความต่างของความสว่างเลย

สีของป้ายข้อความจึงไม่ได้ถูกเลือกด้วยมือ ตัวสร้างธีมและ GoSkin ต่างก็ดัน ความสว่าง — และดันเฉพาะความสว่างเท่านั้น — จนผ่านเกณฑ์บนพาเนลที่ข้อความนั้นวางอยู่จริง เฉดสีและความอิ่มตัวยังอยู่ครบ จานสีจึงรักษาบุคลิกของมันไว้ได้ และการเปลี่ยนจานสีก็ยังรักษาคอนทราสต์ไว้ได้ด้วย

สีที่ถูกอ่านเป็นตัวอักษรกับสีที่ถูกระบายเป็นพื้นที่ ต้องการคนละอย่าง

บนธีมสว่าง สีเตือนต้องเข้มลงเพื่อให้ยังอ่านออกในฐานะตัวอักษร (#96500A) พอสีเติมของแถบสืบทอดค่านั้นไป แถบค่าประสบการณ์ก็กลายเป็นสีน้ำตาล การแก้ด้วยสีอย่างเดียว ไม่ได้ผล: สีเหลืองสว่างโดยธรรมชาติ มันจึงผ่าน 3:1 แม้ไม่มีรางสีเทาอยู่เลย และการทำให้รางเข้มลง ยิ่งแย่กว่าเดิม (1.52 → 1.06)

ทั้งสองอย่างจึงถูกแยกออกจากกัน สียังคงความสด — จานสีบรรจุสีที่ใช้เติมอย่างเดียวไว้ เช่น warning_vivid ส่วนขอบเป็นตัวแบกคอนทราสต์ — GoSkin วาดเส้นขอบ 1dp ให้กับสีเติมทุกสีที่ทำคอนทราสต์ 3:1 กับรางของมันไม่ได้ คำถามที่ว่า "เต็มแค่ไหน" จึงยังอ่านออก 

MY_LIGHT = dict(
    warning=hexc("9A5407"),         # อ่านในฐานะตัวอักษร
    warning_vivid=hexc("F2A007"),   # ระบายลงบนแถบ
)
ถ้าลืมใส่ ระบบจะรายงานให้ทราบ เมื่อไม่มี *_vivid สีเติมที่ออกมาทึมจะทำให้ ตัวสร้างพิมพ์ข้อความ 막대가 칙칙하다 — 팔레트에 warning_vivid 를 더한다 (ภาษาเกาหลี: "แถบดูทึม — เพิ่ม warning_vivid ลงในจานสี") จุดที่เคยเสื่อมคุณภาพอย่างเงียบ ๆ ตอนนี้พูดออกมาแล้ว

พาเนลที่ลอยอยู่ไม่มีทางรู้ว่าข้างหลังมันคืออะไร

HUD ถูกวาดทับฉากเกม — อาจเป็นทุ่งหิมะ หรือถ้ำมืด ถ้าพาเนลของมันกึ่งโปร่งใส สิ่งที่อยู่ข้างหลัง จะทะลุออกมาและเปลี่ยนสีของพาเนล ลากคอนทราสต์ของตัวอักษรลงไปด้วย ที่ความทึบ 82% ตัวอักษรโทนจางของธีมมืดตกลงไปเหลือ 3.74:1 เมื่อพื้นหลังสว่าง — ต่ำกว่าเกณฑ์ขั้นต่ำ

พาเนลกึ่งโปร่งใสจึงถูกวัดโดยมีสีขาวล้วนและดำล้วนอยู่ข้างหลัง เพราะนั่นคือสิ่งที่เลวร้ายที่สุด ที่ฉากเกมจะยัดเยียดให้ได้ พาเนล HUD ของธีมที่แถมมามีความทึบมากพอจะผ่าน (92%) ขณะที่ยังคงลุคใสแบบกระจกไว้

ด้วยเหตุผลเดียวกัน สีของไอคอนก็ไม่ได้ถูกตรึงไว้เช่นกัน สัญลักษณ์ในควิกสล็อตเคยถูกฮาร์ดโค้ด เป็นสีขาวและวัดได้ 1.11:1 บนธีมสว่าง — ตอนนี้มันเดินตามพาเนลที่มันวางอยู่ เหมือนกับที่ป้ายข้อความทำเป๊ะ ๆ

ตัวตรวจสองตัว เอื้อมถึงคนละที่ check_contrast.py อ่านจากไฟล์ธีม ส่วนสีที่สกินผสมขึ้นขณะรัน (ชิป สล็อต) ถูกวัดโดยหัวข้อ skin contrast ของชุดทดสอบที่รันอยู่ใน Godot
