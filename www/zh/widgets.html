控件

每一个都是 .new() 加 add_child() —— 不用场景文件，也不用自动加载。 标有 🛑 的说明都是在真实屏幕上踩过的坑，不是纸上谈兵。

浮动窗口

GoSurface —— 外壳

弹窗、底部面板和下拉菜单用的都是它。它负责安全区域、虚拟键盘、 常驻页眉页脚、滚动主体、谁是最上层窗口、焦点恢复、返回键的归属，以及拖动改变大小。

摆放方式看起来是用在哪里
CENTER屏幕中央的一张卡片确认框、设置
BOTTOM从下方升起的面板列表、管理页面
ANCHOR贴在某个控件旁边的卡片下拉菜单、右键菜单
它不会自己移除自己。 收到 close_requested 之后要隐藏还是释放， 是拥有它的那个界面的事 —— 因为外壳无从知道它为什么被关闭（是保存后关闭，还是丢弃）。

GoSheet —— 从底部升起的页面

var sheet := GoSheet.new()
add_child(sheet)
sheet.open("背包")
sheet.toolbar().add_child(GoStyle.line_edit("搜索…"))
sheet.toolbar().visible = true
sheet.footer().add_child(GoStyle.button("关闭", sheet.close, GoStyle.Tone.PRIMARY))
sheet.footer().visible = true

它自带一个 CanvasLayer，因此能稳稳地盖在 HUD 之上。open() 会清空 主体，并关掉返回按钮和常驻行 —— 在一个无处可返回的界面上留一颗按不动的按钮，看上去就像坏了。

GoDialogs —— 可以 await 的确认框

if await dialogs.confirm("删除存档", "此操作无法撤销。"):
    delete_save()

confirm(title, body, ok_text, cancel_text, extra, args, destructive) —— 正文之后的参数全都可选， alert() 用法相同，只是只有一个按钮。不可撤销的操作请设置 destructive： 确认按钮会变成实心的 GoStyle.Tone.DANGER_SOLID 按钮。 在浅色主题上，带底色的危险文字必须一路压暗到近乎黑色才读得清；实心按钮则保持红底白字。 因为窗口是复用的，每次调用都会重新应用一遍色调；已经开着一个时再调 confirm()，会立刻返回 false。confirm_key() 接受翻译键。

按钮排布。 action_layout 默认是 VERTICAL（对长译文更安全）， HORIZONTAL 表示排成一行、各占一半宽度，AUTO 则只在两个标签都能在卡片一半宽度内单行放下时才排成一行， 否则上下堆叠。action_gap 是按钮之间的间距，body_gap 是按钮上方的间距 —— 把后者调得比按钮间距更大，问题和选项才会读成两个部分。只想改某一个对话框时， 在打开之前调用 set_next_action_layout()。按钮行是在对话框第一次打开时才构建的， 所以把 GoDialogs 放进自动加载也不会在启动时增加任何开销。

GoForm —— 限定最大宽度的表单

它保证其后代的标签会自动换行。 否则一句长句子会拉成一整行，其最小宽度超过屏幕， 两侧被裁掉 —— 甚至会让人看不出自己在哪个界面上。逐个场景手动打开换行，每次都会忘。

GoScroll —— 触摸滚动

里面只放一样东西。页眉和按钮行都该放在外面 —— 长列表绝不能把它们顶出屏幕。 use_panel_edge() 会把滚动条移进卡片已有的内边距里，同时内容保持原来的缩进。

把消息传达给玩家

GoNotice —— 消息条

它从不拦截输入。 提示是用来读的，不是用来按的。它不抢焦点，不挡游戏输入， 底下的按钮照样按得到。需要确认时请用 GoDialogs；需要做选择时用 GoPromptCard。

GoPromptCard —— 不打断游戏的提问

浮在一侧，不加遮罩。游戏照常进行。

GoCoachMark —— 新手引导

一次指向一个真实控件。只有卡片接收输入，所以按下被高亮的控件本身就能推进引导 —— “按这里”于是成了一个动作，而不只是一句话。

tour.start([
    {"target": bag_button, "title": "背包", "body": "捡到的东西都会放进这里。"},
    {"target": map_button, "title": "地图", "body": "按一下打开完整地图。"},
])

title 和 body 既可以是翻译键，也可以是纯文本。目标已经消失的那一步会被跳过。

HUD

好不好看，是小地方决定的

大面板再怎么打磨，真正扎眼的永远是某个小东西：一个词被劈成两截、一圈辉光被切掉、一个挤得慌的快捷槽。 2026-09-13 有人指出了四处这样的问题，修复落在控件和主题里，而不是演示界面上， 这样每一个界面都能得到同样的结果。

看到的现象原因修法
引导标记的 Done 变成了 Don/e 开启换行的按钮会把文字宽度从自己的最小宽度里减掉 —— 一挤就会从词中间断开 GoStyle.fit_words()：单个词永不换行；多个词可以换行，但最长的那个词始终放得下 —— 判断依据是实际显示的文字而不是翻译键，并且语言切换时表单会重新应用一次
通栏按钮左侧的辉光被竖着切掉了 滚动容器一律在自己的边界处裁剪，没有例外。只有右侧因为滚动条留出的空隙才幸存下来 GoScroll 借用父级的内边距，把自己的边界往外推 12dp，再在内部还回去 —— 内容位置不变
快捷槽里的时间、图标和数量竖着堆成一摞 48dp 里塞了三行 图标放大居中，快捷键放左上角，数量做成右下角的角标，剩余时间做成压在图标上的角标 —— 角标面板来自皮肤的 badge_box()
下拉菜单一片扁平，看不出选中了哪一项 选项悬停用的是按钮面板；单选标记用的是引擎那个极淡的默认样式 专门的悬停面板（柔和的强调色底）、与复选框同款的单选图形，以及按触摸尺寸设定的选项高度

给纯图标按钮加一段描述：GoStyle.icon_button(icon, action, -1, tooltip_key) —— 给鼠标用户看的工具提示，和给读屏软件用的无障碍名称，都来自这同一个值。 工具提示由 gohud 自己绘制：引擎的默认实现在宽度计算出错时会把文字拆成一行一个字（实测宽度只有 1dp）。

引导卡片会避开固定部件

横屏时，这张卡片以前会被推到最上边或最下边 —— 而那正是页眉和 HUD 部件所在的位置； 在演示里它就正好压在了页眉的 → × 上。现在它会与目标保持齐平， 绕开任何会预留空间的 GoHudAnchor，还能通过 keep_clear 接收其他需要避开的东西。它以能让开障碍物又不遮住目标的最短距离移动， 屏幕小到无论如何都躲不开时就待在原地 —— 挡住一点也好过整个消失。 它的立体感 —— 让人一眼看出它浮在页面之上 —— 来自皮肤旋钮 （float_shadow_size、float_shadow_lift、float_shadow_alpha；切角皮肤用的是 float_glow_size）。 

tour.keep_clear = [header_bar, toolbar]   # 不是锚点的那些固定部件

有鼠标和键盘的屏幕

手指没有悬停状态。 只照着移动端做，就会有两种只在桌面出现的状态没人检查 —— 其中一种当时确实是坏的：gohud 的焦点框在主按钮上根本看不见。 面板是强调色，焦点框也是强调色：1.00:1，等于用同一种颜色画在自己身上。 用键盘移动时，完全看不出焦点在哪里。

实心按钮（GoPrimaryButton、GoDangerSolidButton）使用与自身面板形成对比的焦点框 —— 深色主题上用深色，浅色主题上用白色，科幻风格下是一副深色瞄准框。对比度检查器测的是 焦点框与它所在的面板，所以换一套调色板这条规则依然成立（WCAG 2.4.11 要求焦点指示器达到 3:1）。

GoHudAnchor —— 九个位置

它会尊重安全区域和边缘留白。给它一个 landscape_spot，横屏时它就会换位置 —— 竖屏时待在底部居中的操控件，横屏可以改到右下角。

它为什么存在。 逐个 HUD 部件手写锚点和偏移，迟早会跑偏：生命条跑到刘海屏的摄像头开孔底下， 操控按钮在横屏时压上手势条。这些算术统一放在一个地方。

别让内容钻到 HUD 底下

当一个可滚动的界面和 HUD 共用屏幕时，内容会从 HUD 底下滑过去，两组文字叠在一起， 最后哪一组都读不出来。这在本插件里发生过两次：输入框的占位文字从快捷槽之间挤了出来， 设置项开关的滑块落在了生命条上。 

form.avoid_hud = true                  # 避开每一个可见的 GoHudAnchor
joystick_anchor.reserve_space = false  # …只在手指按下时才出现的那些除外

每个矩形都朝着损失面积最小的方向避让。右上角的一根状态条，在竖屏手机上是往下绕（占高度的 13%）， 横屏时则往侧边绕（占宽度的 21%）—— 横屏时若竖着避让要付出屏幕的 27%。 已经让出去的地盘会先扣掉，再去测量下一个矩形。

HUD 部件之间也会打架

九个位置把屏幕分好了，却不保证各个部件互不相撞。顶部居中的一条宽消息条， 结结实实地压在了右上角的生命条上，把数值挡住了 —— 你根本看不出还剩多少血。 

notice_anchor.avoid_peers = true      # 落到固定 HUD 的下方
notice_anchor.reserve_space = false   # 而且它显示时不会把页面顶开

它只在竖直方向让位 —— 要是连横向也动，居中的提示条每次出现的位置都不一样。 而且它只避开那些不会自己让位的部件：两边都让，就会永远交换位置换个不停。

GoBar —— 生命、魔法、经验

var hp := GoBar.new()
hp.label_text = "HP"
hp.ink = GoUi.color(GoTheme.DANGER_FILL)   # 仅用于填充的令牌
hp.set_values(320, 500)                     # "320 / 500"

数值变化会在 0.18 秒内缓动 —— 一根直接跳过去的生命条，没法让你感觉到这一下有多重。 reduce_motion 会让它瞬间完成。大数字会缩写成 12.3k， 这样位数增减时状态条的宽度不会抖来抖去。

GoSlot —— 一个快捷槽

图标、数量、冷却和快捷键都在同一个面上。把角标挂在一个小圆圈外面， 会让每个槽宽度都不一样，整排跟着晃。

看得见的大小和能按到的大小不是一回事。 排得紧密的快捷槽，48dp 的触摸区会互相重叠； 重叠部分归中心更近的那个槽 —— 用 touch_peers 让它们互相知道彼此的存在。

keyboard_focus 默认关闭，这样一排八个快捷槽就不会横在键盘用户和后面每一个设置控件之间的 Tab 顺序里。 只有键盘或手柄可用时再把它打开。

GoJoystick —— 虚拟摇杆

模式行为
FIXED永远在同一个位置 —— 不用看也能摸到
FOLLOW拇指按在哪儿它就出现在哪儿
RELATIVE出现之后继续跟着拇指走 —— 长时间移动更省力

moved 传出的 Vector2 长度在 0–1 之间，可以直接乘到速度上； 它不随屏幕尺寸或 DPI 变化。

GoIconButton —— 看着小，按着大

只有在相邻控件不接收输入时才安全。 如果扩大后的区域盖住了下一个按钮， 那个按钮就会失去响应。并排的图标按钮需要 touch_peers。

GoStyle —— 所有东西都在同一处造出来

直接调 Button.new()，内边距、高度和换行就会在不同界面之间一点点跑偏。 这种偏差在代码评审里看不出来，在截图里却一眼就能看到。

带说明的列表行

GoStyle.list_button(GoIconSet.SWORD, "守誓者", _inspect, Color.TRANSPARENT,
    "长剑  /  攻击 42", false)

带第二行的行会获得上下相等的内边距，比单行的行更宽松，标题与说明这一组始终 与图标垂直居中对齐 —— 容器把行拉高时如此，说明换成好几行之后也是如此。整行仍然是一个点按目标。

会自动折行的一排控件

把控件按自然宽度放进 wrap_row。若保持换行开启，按钮的最小宽度会掉到几乎为零， 而这一排会按这个值来分配单元格 —— 标签于是被压成一行一个字。工厂方法替你挡住了这个问题。

永远别让空列表就这么空着

page.add_child(GoStyle.empty_state(GoIconSet.BOX, "这里还什么都没有"))

人看到一片空白，会当成坏了。

子类钩子

每一处构造子控件的地方都走的是可重写的方法，所以继承了 gohud 类型的项目， 不必复制代码就能把自己的子类用到控件内部。

钩子控件默认实现
_make_scroll()GoCoachMark、GoSurfaceGoScroll.new()
_make_close_button()GoPromptCard、GoSurfaceGoIconButton.new()
_make_surface()GoSheet、GoDialogsGoSurface.new()
_should_pause()GoCoachMark模态窗口打开期间隐藏卡片
