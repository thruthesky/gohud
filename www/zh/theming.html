主题

gohud 的外观分成三层。可以只改颜色，也可以把形状整个换掉。

三层结构

一套预设把三层打包在一起。留空的字段会回退到默认值。

层决定什么怎么改
Theme 颜色、尺寸、文字缩放，以及引擎自己绘制的一切的形状 —— 按钮面板、输入框、标签页、开关贴图 手写一份 .tres，或用 tools/make_theme.py 生成
GoSkin 由代码绘制的一切的形状 —— 摇杆、快捷槽的面、引导标记的光圈、标签片、骨架屏、分隔线、分节标题 继承它，只重写你在意的那几个方法
GoIconSet 按名字取用的图标 —— 84 个默认图形，或者中世纪图标集覆盖其上的 16 个雕刻图形。可以是贴图包，也可以是图标字体；调用方的代码完全一样 提供一整套，或者只覆盖其中几个名字
为什么光有 Theme 还不够。 StyleBoxFlat 只有圆角这一种角 —— 把半径设成零得到的是直角，中间没有别的可能。斜切的角、单独一条加粗的边、外发光：引擎一个都画不出来。 而摇杆和引导标记是在 _draw() 里画的，主题根本够不着那里。

挑一套

GoUi.use_preset(GoThemePresets.SCIFI_DARK)

这一行会把主题、皮肤和图标一起换掉。在编辑器里可以用 项目设置 → Gohud → Theme → Preset；用设置资源的话就是 GoConfig.preset。

保留其中一项由自己决定

GoUi.use_preset(GoThemePresets.SCIFI_DARK)
GoUi.config.icons = my_icons     # 图标用自己的，其余全部用预设的

显式设置 theme、skin 或 icons 会压过预设。

中世纪：铁、皮革与羊皮纸

medieval_dark 把暗铁和皮革配上仿古金，medieval_light 则用羊皮纸和墨水。两者都使用 GoSkinMedieval、现有的控件，以及 16 个带雕刻细节的原创图标； 导航类图标回退到原本的图标集。

GoUi.use_preset(GoThemePresets.MEDIEVAL_DARK)
# 或者：GoUi.use_preset(GoThemePresets.MEDIEVAL_LIGHT)

请在创建 UI 之前选好预设。显式设置的 GoConfig.theme、 skin 或 icons 依然优先。打开 res://addons/gohud/examples/medieval/medieval.tscn 并按 F6，就能看到一套能用的 角色面板、行囊和任务日志。里面的按钮可以切换风格变体并打开物品详情。

菜单边框带一颗铆钉和小小的角落纹饰；常驻显示的 HUD 则保持素净的边。 生命、魔法和耐力分别用红、蓝、橄榄绿填充。Cinzel 只用在标题和副标题上； 正文仍沿用宿主项目或默认的字体。随包字体的许可证放在 assets/fonts/cinzel/OFL.txt。

雕刻图标集重画了 bag、book、box、coin、crown、 flag、heart、key、map、potion、shield、 star、sword 和 user，另外新增了 scroll 和 seal。 其余名字一律回退到默认集，所以 close 和 settings 在任何预设下都保持默认图形。 Cinzel 只覆盖拉丁字母；本地化后的标题请通过 shape.fonts 指定各自的字体。

测试套件对两个变体都检查了什么。 中世纪皮肤确实被选中；菜单和 HUD 面板是锻造边框，且纹饰只出现在菜单上； 标题使用 Cinzel 而正文保持继承来的字体；雕刻图标以 DPITexture 导入； 真实的快捷槽确实用上了该皮肤；改动一份皮肤副本的旋钮能传到快捷槽而不必碰预设； 切回去之后默认和科幻的几何形状能够恢复。

JSON 主题可以继承别的 JSON 主题。省略的值沿用父主题的设置； 循环继承会被拒绝。生成出来的预设会保留父主题的图标集。

设置项效果
shape.material0：铁 · 1：皮革 · 2：羊皮纸。决定表面的纹路。

令牌

每一种颜色和尺寸都放在 Theme 的 GoHud 类型下，按名字取用。 不写死数字是铁律：换主题的时候，名字会自己跟上。 

GoUi.color(GoTheme.ACCENT)             # 颜色
GoUi.metric(GoTheme.GAP)               # 尺寸（dp）
GoUi.font_size(GoTheme.ROLE_CAPTION)   # 某个文字角色的字号
GoUi.box(GoTheme.BOX_CARD)             # 一份 StyleBox 的副本

StyleBoxFlat 画不出来的形状

类它画出什么
GoStyleBoxCut斜切的角、一条加粗的强调边、外发光
GoStyleBoxBracket只画四角的标记，不把内容围起来
GoStyleBoxMedieval锻造边框 —— 铆钉、角落雕花、斜面高光，以及铁、皮革或羊皮纸的纹理

三者都能像别的 StyleBox 一样序列化进 Theme 资源 —— 正是这一点让主题能够改变形状。

内边距要通过 content_margin_* 给。 在 GDScript 里继承 StyleBox 意味着 _get_style_margin() 永远不会被调用（在 Godot 4.7 上实测）。请把内置字段填上， 否则内容会紧贴边框。

你自己的预设 —— 一个文件

从前加一套主题意味着手工改四个地方 —— 生成器的调色板、形状、一份皮肤、一份预设资源。 现在一条命令就把它们全部就位。 

python3 addons/gohud/tools/new_theme.py neon --from scifi_dark --title "Neon"
python3 addons/gohud/tools/make_theme.py neon      # 主题 .tres + 控件贴图
godot --headless --path . --import                  # 把新贴图导入一次
GoUi.use_preset(&"neon")                             # 完成 —— 它也会出现在选择器里

第一行会写出 themes/palettes/neon.json 和 themes/presets/neon.tres。 这份 JSON 会把所继承主题的每一个值都完整列出来，因此它同时也是一份“能改什么”的清单： 删掉一个键就沿用父主题的值，写上一个键就覆盖它。预设是通过扫描 themes/presets/ 找到的，所以不必改任何注册表代码 —— 项目设置里的下拉框也会自动认出它。

继承皮肤（可选）

只有主题和形状够不着的东西 —— 摇杆的六边形、快捷槽角标、引导标记的瞄准框 —— 才住在皮肤里。继承 GoSkin，只重写那几个方法，再把 JSON 的 skin 指向那份资源。只改颜色的主题可以跳过这一步。

有一项检查在替这个承诺兜底。 tools/check_scaffold.sh 每次运行都会造一套一次性主题 —— 改掉强调色、把圆角设成 4 —— 并验证生成、令牌传播和对比度全过之后再把它删掉。 第一次运行就发现：一套只改了强调色的主题竟有 8 对颜色不达标 —— 生成器推高了文字颜色，却原封不动地用了强调色。现在它连强调色和压在上面的文字也一起推。

可读性是量出来的

“好看”是口味问题；“看得清”却可以测量。 灰得发淡的文字在好显示器上没问题， 到了白天的手机屏上就消失了 —— 靠眼睛挑颜色，迟早会出这种事。 

python3 addons/gohud/tools/check_contrast.py
对象要求
正文文字4.5 : 1
大号文字（24px 及以上）3 : 1
强调色的边框和图标3 : 1
装饰性边框2 : 1 —— WCAG 的 3:1 规则不适用于纯装饰
相邻表面1.12 : 1 —— 足以让卡片从背景中区分出来

同色相文字压在同色相底色上

这个坑在本项目里出现过三次 —— 按下状态的按钮（强调色面板配强调色文字）、 危险按钮，以及标签片。它在色卡上看着挺好，一测就崩， 因为两者色相相同，明度上也就没有差别。

所以文字颜色不是手工挑的。主题生成器和 GoSkin 各自只推明度 —— 而且只推明度 —— 直到它在文字真正落脚的那块面板上达标为止。色相和饱和度保持不变， 因此调色板保留了自己的性格，改动它也不会丢掉对比度。

当文字读的颜色和当色块涂的颜色，要求正好相反

在浅色主题上，警告色当文字用时必须压暗才读得清（#96500A）。 而状态条的填充要是继承了这个值，经验条就变成褐色了。光靠颜色解决不了： 黄色本身就亮，所以哪怕底槽完全不加灰也能过 3:1，而把底槽压暗只会让情况更糟（1.52 → 1.06）。

于是把两者分开。颜色保持鲜艳 —— 调色板里带有仅用于填充的颜色，例如 warning_vivid。对比度交给边缘来扛 —— 只要某个填充在自己的底槽上达不到 3:1， GoSkin 就给它画一圈 1dp 的描边，这样“到底满了多少”依然看得清。 

MY_LIGHT = dict(
    warning=hexc("9A5407"),         # 当文字读
    warning_vivid=hexc("F2A007"),   # 涂在状态条上
)
漏写了会被报出来。 少了 *_vivid 时，若填充色算出来偏暗，生成器就会打印 막대가 칙칙하다 — 팔레트에 warning_vivid 를 더한다（生成器实际输出的原文，意为“状态条发暗 —— 请在调色板里加上 warning_vivid”）。 以前会悄悄劣化的地方，现在会开口说话。

浮动面板不可能知道自己背后是什么

HUD 是画在游戏画面之上的 —— 背后可能是雪原，也可能是洞窟。如果它的面板半透明， 背后的东西就会透上来，改变面板的颜色，文字对比度也跟着被拖下去。 在 82% 不透明度下，深色主题的弱化文字在明亮背景上掉到了 3.74:1 —— 低于下限。

所以半透明面板一律以纯白和纯黑作为背景来测量；游戏场景能给出的最坏情况也就是这两种了。 随包主题的 HUD 面板不透明到足以达标（92%），同时仍保留那种玻璃质感。

同理，图标颜色也不写死。快捷槽里的图形原本被硬编码成白色，在浅色主题上量出 1.11:1 —— 现在它会跟随自己所在的面板，和文字的做法完全一样。

两个检查器，两段够得着的范围。 check_contrast.py 读的是主题文件； 皮肤在运行时混出来的颜色（标签片、快捷槽）则由测试套件在 Godot 内部的 skin contrast 一节来测量。
