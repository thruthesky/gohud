游戏 UI，用一份资源驱动

gohud 是面向 Godot 4.7 及以上版本的 HUD 与 UI 套件。浮动窗口、底部面板、对话框、表单、 消息条、引导标记、HUD 状态条、快捷槽和虚拟摇杆全都由一份主题和一份可替换的图标集驱动， 安全区域、虚拟键盘、RTL 和触摸目标都替你处理好。 十四套预设 —— 默认、科幻、中世纪、Material 3、儿童、漫画和街机，每种各有深色与浅色 —— 一行代码就能换掉颜色和形状。

新增：街机、漫画、Material 3，以及给孩子们的外观

四个新系列加入了默认、科幻和中世纪的行列——现在共有十四种内置外观，每种都有深色和浅色。 每个控件、弹窗和 HUD 部件都能直接用上它们，代码一行都不用改：换掉预设，整个画面就跟着变。

Material 3 —— 面向应用界面

对照官方 M3 令牌逐项核对的 Material 3 Expressive：48dp 触摸目标里带 40dp 底板的胶囊按钮、 28dp 的对话框和底部面板、填充卡片、描边输入框，以及 Expressive 滑块。应用组件——导航栏、顶部应用栏、FAB、 搜索栏、纸片、进度和日期选择器——遵循 M3 组件令牌，标题使用随包附带的 Roboto。适合商店、设置、收件箱，以及每一个应该让人感觉像应用的界面。

儿童 —— 玩具箱

为孩子们而做：每个按键、列表行和面板都是一颗果冻糖，带粗描边和一道实心底边，按下时会陷进去； 每类控件各有自己的蜡笔颜色。快捷槽是糖果方块，徽章是贴纸，摇杆是一道彩虹，窗口带阳光色的标题彩带和 圆形的糖果关闭按钮，按下去还会被压扁。尺寸和你项目的字体都保持原样。

漫画 —— 粗墨线

每个表面都是一格漫画分镜：粗墨线描边里填着表面颜色，背后衬一道硬阴影，表面被按下时阴影随之消失。 一个设置开关所有阴影，另外两个设置决定描边粗细和阴影大小，一次调用就能对单个控件做同样的事。窗口带黄色的标题框。

街机 —— 上色的按键

每个按键都上了色——渐变、一道白色高光和按下时会陷进去的底边，全都装在藏青色的墨线描边里—— 标签是带墨线描边的白字：开始用绿色，其余用蓝色，删除用红色。面板很厚，一圈彩色边框围着浅色内芯； 窗口带金色的标题横幅和一个圆形的红色关闭键。

GoUi.use_preset(GoThemePresets.MATERIAL_LIGHT)   # 或 MATERIAL_DARK
GoUi.use_preset(&"kids_light")                   # 或 &"kids_dark"
GoUi.use_preset(&"comic_light")                  # 或 &"comic_dark"
GoUi.use_preset(&"arcade_light")                 # 或 &"arcade_dark"

街机：上色的按键与厚实的面板

这款最新的外观把每个画面都打扮成一台街机。每个按键都上了色——从浅色顶部过渡到深色底部的渐变、 一道白色高光和按下时会陷进去的底边，全都装在藏青色的墨线描边里——标签是带墨线描边的白字。 每块面板都很厚：一圈自带高光的彩色边框围着浅色内芯。 arcade_light 在天蓝色页面上放白色面板；arcade_dark 在夜色页面上放藏青色面板。 下面每一张图都是真实的 gohud 画面——同样的代码，只差一行预设。 

GoUi.use_preset(&"arcade_light")   # 或 &"arcade_dark"

夜里：arcade_dark

在深色页面上，墨色变得深得多，成了页面本身，而按键的颜色依旧鲜亮。

街机外观是怎么做到的

表面

每个按键和面板都是一个 GoStyleBoxArcade：墨线描边、渐变主体、底边和高光，全都画在控件自己的矩形里—— 按键在各种状态下大小不变，按下只是让它陷进去。

看得清的标签

带墨线描边的白色标签，在描边能隔开的任何颜色上都看得清——WCAG 把描边算作字母的一部分。 每种颜色都会被调整，直到它的标签在渐变的每个高度上都超过 4.6:1。

窗口

窗口标题以带墨线描边的白字放在金色横幅上，旁边是一个圆形的红色关闭键。对话框、底部面板、抽屉和弹出气泡都是 带厚边框的面板。

单个按键可以有自己的颜色——比如暂停菜单里一个橙色的商店键：

menu.add_child(GoStyle.arcade_paint(GoStyle.button("Shop", _shop), Color("#FF8A1E")))

漫画：粗墨线与硬阴影

漫画外观把每个表面都画成一格漫画分镜——粗墨线描边里填着表面颜色， 向右下方投出一道坚实的硬阴影。comic_light 在纸张般的奶油色页面上用黑墨描画，主色为钴蓝； comic_dark 在夜色页面上用奶油色墨线描画，主色为黄色。下面每一张图都是 真实的 gohud 画面——同样的代码，只差一行预设。 

GoUi.use_preset(&"comic_light")   # 或 &"comic_dark"

每个控件都描上墨线

按钮、开关、标签页、滑块、卡片、表单、表格、选择器和纸片全都描上了墨线——不必一个个 去设置样式。按下一个按键，它的阴影就消失：表面像盖章一样沉进自己的位置。 禁用的表面失去阴影并变淡，能按的和不能按的一眼就分得清。

夜里：comic_dark

在深色页面上黑色描边会消失不见，所以 comic_dark 用奶油色画描边，并投下一道带着同样墨色的 淡淡阴影。HUD 部件——快捷槽、进度条、摇杆和奖励日历——遵循同样的规则。

漫画外观是怎么做到的

所有表面共用一个 StyleBox

每个表面都是一个 GoStyleBoxComic：填充、描边和阴影，都画在控件自己的矩形之内。它每次绘制时都从 GoConfig 读取描边和阴影的大小，所以改一个设置，整个画面立刻一起变。

按下就是平的

按下的按键收起阴影，挪进阴影的位置。悬停时阴影保留；获得焦点时加一圈内侧墨线环，绝不会盖住描边；禁用的表面失去阴影并变淡。

其余的交给皮肤描线

GoSkinComic 给代码画出的部分描上墨线：快捷槽、纸片、徽章、头像、提示、导航栏、FAB、日期格子，还有摇头会投下阴影的摇杆。

窗口有标题框

窗口标题放在一个黄色标题框里，就像漫画里的旁白框，旁边是一个描了墨线的圆形关闭按钮。对话框、底部面板、抽屉和气泡弹层都是不透明的墨线面板。

白天黑夜都清晰可读

两套调色板都和其他所有预设一样通过 WCAG 对比度检查，按下和禁用的按键也不例外。当标题框的颜色与页面太接近时，它的描边会退回到页面颜色。

布局不变

描边和阴影都收在每个控件之内，内边距保持主题给的样子，所以用别的外观排好的界面会保持原有布局——你项目的字体也一样。

三个设置和一次调用

三个 GoConfig 设置会一次改变所有漫画表面。不需要重建任何东西——设置的同时画面就会重绘。

GoUi.config.comic_border_width = 2.0   # 描边（dp）——默认 3
GoUi.config.comic_shadow_size = 6.0    # 阴影（dp）——默认 4
GoUi.config.comic_shadow = false       # 所有地方都不要阴影

单个控件可以不理会设置，自行其是。把 true 作为最后一个参数传入，就连它里面的一切都包括在内。

GoStyle.comic_shadow(skip_button, false)     # 这个按钮平贴着
GoStyle.comic_shadow(card, true, true)       # 这张卡片及其中的一切保留阴影
GoStyle.comic_border(title, 5.0)             # 只给这一个加粗描边
造一个自己的漫画外观。tools/new_theme.py inked --from comic_light 会复制调色板；改掉纸张、 墨线和主色，再运行 tools/make_theme.py inked。墨线、阴影和皮肤都会一并带上。

它替你接手了什么

游戏 UI 最费时间的从来不是按钮长什么样，而是那些会在各种设备之间慢慢跑偏的东西。 gohud 把这些偏差集中到一处处理。

每个尺寸都是一个令牌

间距、圆角和字号都按名字取用，而不是写死数字。换掉主题，整个画面跟着一起变。

看得见的大小 ≠ 按得到的大小

关闭按钮看上去是 36dp，触摸目标却有 48dp。密集的快捷槽互相重叠时，中心更近的那个接住这次点按。

刘海与键盘

HUD 各部件待在安全区域之内，虚拟键盘弹出时输入框会抬到键盘上方。

返回只关掉一层

Esc 和安卓返回键只关闭最上面那一层。叠起来的窗口不会一起消失。

提示条从不抢走输入

隔着消息条按下去，底下的按钮照样收到。焦点也不会被夺走。

图标按名字取用

控件只认识 GoIconSet.CLOSE。换掉图标集，所有画法随之改变，一行代码都不用动。 图标 →

十四种外观，一行代码

GoUi.use_preset() 把主题、皮肤和图标一起换掉 —— 圆角、科幻切角、锻造的中世纪边框、Material 3 的应用组件、儿童的果冻糖、漫画的墨线，或是街机的彩漆。

可读性靠量出来

每套主题都对照 WCAG 检查过，连按钮的各种状态和盖在纯白、纯黑之上的半透明 HUD 面板也不例外。

不启用插件也照样能用。 启用之后会多一个 GoRuntime 自动加载节点，用来跟踪窗口尺寸、dp 缩放和键盘高度， 再加上配置资源和预设的项目设置项 —— 这些是方便，不是必需。

换外观 —— 换颜色，也换形状

Theme 只能改引擎自己绘制的那部分。StyleBoxFlat 只有圆角这一种角，而摇杆、快捷槽和引导标记是用代码画的 —— 所以光靠主题永远改不了它们的形状。为此 gohud 提供了预设：把一份主题、一份皮肤和一份图标集打包成一个整体。

同一个界面，在手机上和在桌面上

画廊截图是竖屏手机。下面是同一份代码在 1280×800 下的样子 —— 内容停在便于阅读的宽度（480dp）并居中， HUD 仍待在四角。表单会绕开浮动的 HUD 部件，但本来就没挡住时不会移动： 在宽屏上硬推一把，只会让内容偏离中心。

同一个面板，不同的外观

在项目设置 → gohud → Theme → Preset 里挑一套，或者设置 GoConfig.preset。 显式填写 theme、skin 或 icons 会压过预设， 所以你可以在一套预设的基础上只覆盖其中一项。

一套新主题就是一个 JSON 文件。 new_theme.py kingdom --from medieval_dark 会写出一份把所有继承值都列全的调色板；make_theme.py kingdom 生成主题、控件贴图和皮肤旋钮， 随后这套预设就会出现在选择器里。全部设置项与旋钮 →

皮肤 —— Theme 够不着的地方

皮肤管着摇杆、快捷槽的面、引导标记的光圈、标签片、骨架屏、内联提醒、分隔线和分节标题。 继承它，只重写你想改的部分。 

class_name MySkin extends GoSkin

func slot_box(accent: Color, lit: bool) -> StyleBox:
    var box := GoStyleBoxCut.new()
    box.bg_color = accent
    box.cut = 6.0
    box.edge_color = accent
    return box
类能画出的形状
GoStyleBoxCut斜切的角（切角）、一条加粗的强调边、外发光
GoStyleBoxBracket只画四角的标记，不把内容围起来
GoStyleBoxMedieval锻造边框，带铆钉、角落雕花、斜面高光和材质纹理
GoStyleBoxJelly果冻糖——粗描边、按下时会陷进去的实心底边、上浅下深的糖体，以及一道白色高光
GoStyleBoxComic漫画分镜——粗墨线描边和硬投影，两者的大小都在游戏运行时由 GoConfig 决定
GoStyleBoxArcade街机的按键或面板——渐变主体、白色高光、按下时会陷进去的底边和墨线描边；面板再加一圈厚厚的彩色边框围着浅色内芯

六者都能序列化进 Theme 资源 —— 正是这一点让主题不只能换颜色，还能换形状。 GoSkinSciFi、GoSkinMedieval、GoSkinMaterial、GoSkinKids、GoSkinComic 和 GoSkinArcade 是随包提供的子类。

GoStyle.box() 永远返回 StyleBoxFlat，因为调用方拿到它之后 还要调整 bg_color 或 corner_radius。需要保住自定义形状时， 请改用 GoStyle.surface()。

可读性是量出来的，不是看出来的

“好看”是口味问题；“看得清”却可以测量。 灰得发淡的文字在好显示器上没问题， 到了白天的手机屏上就消失了 —— 靠眼睛挑颜色，迟早会出这种事。 

python3 addons/gohud/tools/check_contrast.py

十四套主题里的每一对颜色，以及每个按钮状态下的文字与它所在的面板，都会拿去对照 WCAG 测量。 半透明颜色会先与真实背景合成再测 —— 直接测半透明色，得到的比值会比屏幕上实际看到的更好看。

因此文字颜色是推导出来的，而不是挑出来的：生成器以调色板里的值为起点，不断推高它的明度， 直到它在每一个可能落脚的面上都达标为止。改了调色板，对比度会自动跟上。 这些规则以及背后的坑 →

检查、发布与这个网站

一个入口跑完所有检查；每一部分都能发现其他部分看不到的问题。

bash addons/gohud/tools/check_all.sh
检查能抓到什么
四种屏幕尺寸下的 run_tests.sh控件行为与布局、RTL 下的位置、键盘焦点、运行时皮肤对比度、全部预设
new_project_check.sh对宿主项目的隐藏依赖；加 --zip 检查实际发布的压缩包，加 --export 检查 Web 构建
check_contrast.py每个主题文件的 WCAG 对比度，含按钮各状态与半透明面板
check_generated.py · check_scaffold.sh生成的主题与其调色板一致；临时主题能成功生成并通过对比度检查
check_package.py采用 package.json 的版本号、变更日志的搬移和 ZIP 内容，全部在临时副本中验证
check_site.py本站的链接、锚点、页面语言、术语表和旋钮表格
最近一次记录在案的运行 —— 2026-09-13，Godot 4.7.2，macOS，Compatibility 渲染器。 在空项目中于 390×844、844×390、768×1024 和 1280×800 下 438 项检查全部通过；加上 GoRuntime 自动加载后再次 438 项全过； 完成一次 Web 导出；六套主题对比度零失败。这一轮没有覆盖 Android 或 iOS 真机。

发布版本

cat addons/gohud/package.json       # { "version": "1.1.0" }
bash addons/gohud/tools/release.sh  # 全部检查 → ZIP → 在空项目中验证
bash addons/gohud/tools/package.sh  # 1.1.0 → builds/1.1.0/gohud-1.1.0.zip

版本号就是 package.json 里写的那个，打包绝不会自动递增。 要发布新版本，先改这个数字。 运行成功会把 plugin.cfg 和 GoUi.VERSION 设为该版本，并且只在该版本第一次打包时，把 CHANGELOG.md 中 Unreleased 下的记录挪进带日期的条目。 同一版本再次打包会重新生成 ZIP 并替换旧的。运行失败则什么都不改。 ZIP 里不包含这个网站、测试、工具和 package.json。

这个网站

python3 addons/gohud/tools/make_site.py            # 术语表和皮肤旋钮表格，直接从源码生成
python3 addons/gohud/tools/check_site.py           # 检查链接、锚点、语言、术语表和生成的表格
bash addons/gohud/tools/site_shots.sh /tmp/shots   # 为每个页面截取桌面版和手机版截图

这些页面就是 www/ 下的普通 HTML —— 根目录是英文，ko/ 是韩文。 一个 GitHub Actions 工作流把那个文件夹作为站点根目录发布出去。
