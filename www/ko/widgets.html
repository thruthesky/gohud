위젯

전부 .new() 로 만들어 add_child() 하면 된다. 씬 파일도, 오토로드도 필요 없다. 아래 설명에서 🛑 표시가 붙은 것은 실제 화면에서 부딪혀 본 함정이다.

떠 있는 창

GoSurface — 창의 껍데기

팝업·시트·드롭다운이 전부 이것 하나를 쓴다. 안전영역·가상 키보드·고정 머리말/바닥·스크롤 본문· 가장 위 창 판정·포커스 복원·뒤로가기 소유권·끌어서 높이 조절을 한 곳에서 처리한다.

배치모습쓰는 곳
CENTER화면 가운데 카드확인창·설정
BOTTOM아래에서 올라온 시트목록·관리 페이지
ANCHOR지정한 컨트롤 옆에 붙는 카드드롭다운·컨텍스트 메뉴
스스로 사라지지 않는다. close_requested 를 받아 숨기거나 지우는 것은 소유한 화면이다 — 왜 닫히는지(저장하고 닫기 vs 버리고 닫기)는 껍데기가 알 수 없다.

GoSheet — 아래에서 올라오는 페이지

var sheet := GoSheet.new()
add_child(sheet)
sheet.open("가방")
sheet.toolbar().add_child(GoStyle.line_edit("검색…"))
sheet.toolbar().visible = true
sheet.footer().add_child(GoStyle.button("닫기", sheet.close, GoStyle.Tone.PRIMARY))
sheet.footer().visible = true

자체 CanvasLayer 를 가져 HUD 위에 확실히 올라온다. open() 은 본문을 비우고 뒤로 버튼·고정 줄을 끈다 — 돌아갈 데가 없는 화면에 죽은 버튼이 남으면 누른 사람은 그것을 고장으로 읽는다.

고정 줄과 스크롤 본문을 나누는 이유. 확인·취소를 body 에 넣으면 목록이 길어질 때 화면 밖으로 밀린다. footer() 는 언제나 보인다.

GoDialogs — await 로 받는 확인·알림

if await dialogs.confirm("저장 삭제", "되돌릴 수 없습니다."):
    delete_save()

confirm(title, body, ok_text, cancel_text, extra, args, destructive) — 본문 뒤는 전부 생략할 수 있고, alert() 는 버튼 하나로 같은 방식이다. 되돌릴 수 없는 일에는 destructive 를 켠다 — 확인 버튼이 채워진 GoStyle.Tone.DANGER_SOLID 버튼이 된다. 밝은 테마에서 옅게 물든 위험 버튼의 글자는 읽히려고 어두워지다 결국 검은 글자로 보이지만, 채워진 버튼은 빨간 판에 흰 글자를 지킨다. 창 하나를 재사용하므로 부를 때마다 색을 다시 입히고, 이미 떠 있을 때 부른 confirm() 은 곧바로 false 다. 번역 키로 물을 때는 confirm_key().

버튼 배치. action_layout 기본은 VERTICAL(긴 번역에도 안전)이고, HORIZONTAL 은 반씩 한 줄, AUTO 는 두 문구가 반 폭에 한 줄로 들어갈 때만 한 줄로 두고 아니면 세로로 접는다. action_gap 은 버튼 사이, body_gap 은 본문과 버튼 줄 사이 간격이다 — 버튼 사이보다 넓게 두면 "질문" 과 "고르기" 가 두 덩어리로 읽힌다. 창 하나만 다르게 하려면 열기 직전에 set_next_action_layout(). 버튼 줄은 처음 열 때 지어지므로 오토로드로 둔 GoDialogs 는 부팅 비용이 늘지 않는다.

GoForm — 폭을 제한하는 폼

브레이크포인트마다 최대 폭이 다르고, 가상 키보드가 올라오면 입력 칸이 그 위로 온다.

자손 라벨의 줄바꿈을 보장한다. 없으면 긴 문장 하나가 한 줄로 뻗고, 그 최소 폭이 화면을 넘겨 좌우가 잘린다 — 무슨 화면인지조차 분간할 수 없게 된다. 씬마다 손으로 켜는 방식은 반드시 빠뜨린다.

GoScroll — 손가락 스크롤

안에 하나만 넣는다. 머리말과 버튼 줄은 밖에 둔다 — 목록이 길어지면 그것들이 화면 밖으로 나가면 안 된다. use_panel_edge() 를 부르면 스크롤바가 카드의 기존 여백 자리로 나가고 내용은 원래 들여쓰기를 유지한다.

알리기

GoNotice — 스낵바

새 메시지가 이전 것을 덮어쓰고 시간이 지나면 사라진다.

절대 입력을 가로채지 않는다. 알림은 읽는 것이지 누르는 것이 아니다. 포커스를 훔치지 않고, 게임 입력을 막지 않으며, 그 아래의 버튼이 그대로 눌린다. 확인이 필요하면 GoDialogs, 선택이 필요하면 GoPromptCard 다.

GoPromptCard — 화면을 막지 않는 질문

스크림 없이 화면 한쪽에 떠서 묻는다. 게임은 계속 돈다.

GoCoachMark — 안내 투어

실제 화면의 컨트롤을 하나씩 가리키며 무엇인지 알려 준다. 카드 영역만 입력을 받으므로 가리킨 컨트롤을 실제로 누르면 다음 단계로 넘어간다 — "여기를 누르세요" 가 말이 아니라 동작이 된다.

tour.start([
    {"target": bag_button, "title": "가방", "body": "주운 물건이 여기 모입니다."},
    {"target": map_button, "title": "지도", "body": "눌러서 전체 지도를 엽니다."},
])

title·body 는 번역 키여도, 그대로 쓸 문구여도 된다. 대상이 사라진 단계는 건너뛴다.

HUD

작은 것들이 예쁨을 정한다

큰 판은 잘 다듬어도, 눈에 걸리는 건 언제나 작은 데다 — 두 줄로 갈라진 낱말, 뚝 잘린 글로우, 비좁은 슬롯. 2026-09-13 에 지적받은 네 가지를 위젯·테마 차원에서 고쳤다. 화면(데모)이 아니라 부품을 고쳤으므로 어느 화면에서든 같은 결과다.

보였던 것원인고친 것
코치마크의 Done 이 Don/e 줄바꿈이 켜진 버튼은 최소 폭에서 글자 폭을 뺀다 — 좁아지면 낱말 안에서 끊는다 GoStyle.fit_words(): 한 낱말은 접지 않고, 여러 낱말은 가장 긴 낱말 폭을 보장 — 번역 키가 아니라 보이는 글자로 판단하고, 언어가 바뀌면 폼이 다시 입힌다
꽉 찬 폭 버튼의 글로우가 왼쪽에서 세로로 잘림 스크롤은 자기 경계에서 무조건 자른다. 오른쪽만 레일 자리 덕에 살아남아 좌우가 달랐다 GoScroll 이 부모 여백을 빌려 경계를 12dp 바깥으로 밀고, 안쪽에서 되돌려 내용은 제자리
슬롯에 시간·아이콘·수량이 세로로 쌓여 비좁음 48dp 안에 세 줄 아이콘은 가운데에 크게, 단축키는 왼쪽 위, 수량은 오른쪽 아래 배지, 남은 시간은 아이콘 위 배지 — 배지 판은 스킨의 badge_box()
드롭다운 메뉴가 밋밋하고 어느 항목이 골라졌는지 안 보임 항목 호버에 버튼 판을 쓰고, 라디오 표시는 엔진 기본(흐린 원) 항목 전용 호버 판(옅은 강조 채움) · 체크박스와 같은 라디오 그림 · 항목 높이를 터치 기준으로

아이콘만 있는 버튼에는 GoStyle.icon_button(icon, action, -1, tooltip_key) 로 설명을 단다 — 마우스 사용자에게는 툴팁이, 화면 낭독기에게는 접근성 이름이 그 한 값에서 나온다. 툴팁은 gohud 가 직접 그린다: 엔진 기본 툴팁은 폭 계산이 어긋나면 글자를 한 자씩 세로로 쪼갠다(실측 폭 1dp).

코치마크 카드는 붙박이를 덮지 않는다

가로 화면에서 카드를 화면 맨 위·아래 끝으로 보내던 규칙이 문제였다 — 그 띠에는 머리띠와 HUD 가 산다. 데모에서 카드가 헤더의 → × 를 덮었다. 이제 카드는 대상과 같은 높이에 놓이고, 자리를 예약한 GoHudAnchor 를 알아서 피하며, 앵커가 아닌 것은 keep_clear 로 알려 준다. 피할 때는 대상을 가리지 않는 방향 중 가장 짧게 옮기고, 다 피할 수 없으면 그대로 둔다 — 카드가 사라지는 것보다 겹치는 편이 낫다. 카드가 본문 위에 떠 있다 고 읽히도록 그림자는 스킨 다이얼 (float_shadow_size·float_shadow_lift·float_shadow_alpha, 사선 판은 float_glow_size)로 깊이를 둔다. 

tour.keep_clear = [header_bar, toolbar]   # 앵커가 아닌 붙박이

마우스와 키보드가 있는 화면

손가락에는 호버가 없다. 그래서 모바일만 보고 만들면 데스크톱에서만 나타나는 두 상태가 검증 없이 지나간다 — 실제로 gohud 의 포커스 링이 강조 버튼 위에서 보이지 않았다. 판이 바로 강조색인데 링도 강조색이라 1.00:1, 즉 같은 색이 겹쳐 사라진 것이다. 키보드로 옮겨 다니면 "지금 어디" 를 알 수 없었다.

채워진 버튼(GoPrimaryButton · GoDangerSolidButton)은 판과 대비되는 링을 쓴다 — 어두운 테마에서는 짙은 링, 밝은 테마에서는 흰 링, sci-fi 에서는 어두운 조준 표식이다. 대비 검사가 포커스 링을 그것이 얹히는 판 위에서 재므로, 팔레트를 바꿔도 이 규칙이 남는다 (WCAG 2.4.11 은 포커스 표시에 3:1 을 요구한다).

HUD 위젯

GoHudAnchor — 화면 아홉 자리

안전영역과 가장자리 여백을 알아서 지킨다. landscape_spot 을 주면 가로 화면에서 다른 자리로 옮겨 간다 — 세로에서 아래 가운데에 있던 조작부를 가로에서는 오른쪽 아래로 보내는 식이다.

왜 필요한가. HUD 조각마다 앵커와 오프셋을 손으로 쓰면, 노치가 있는 기기에서 체력바가 카메라 구멍에 가리고 가로 모드에서 조작 버튼이 제스처 바에 걸린다. 그 계산을 한 곳에 둔다.

본문이 HUD 뒤로 흐르지 않게

스크롤되는 화면이 HUD 와 한 화면에 있으면, 본문은 HUD 뒤를 지나간다 — 글자끼리 겹쳐 둘 다 못 읽게 된다. 이 애드온에서 실제로 두 번 일어났다: 입력칸 자리표시자가 퀵슬롯 사이로 삐져나왔고, 설정 토글의 손잡이가 체력바 위에 얹혔다. 

form.avoid_hud = true                  # 보이는 GoHudAnchor 를 모두 피한다
joystick_anchor.reserve_space = false  # 손을 얹을 때만 나타나는 것은 빼고

칸마다 잃는 면적이 가장 작은 방향으로 피한다. 오른쪽 위의 체력바는 세로 화면에서는 아래로 (높이의 13%), 가로 화면에서는 옆으로(폭의 21%) 비껴간다 — 가로에서 세로로만 피하면 본문이 화면의 27% 를 잃는다. 이미 물러난 만큼은 다음 칸을 잴 때 빼고 본다.

HUD 끼리도 겹친다

아홉 자리는 화면을 나눌 뿐, 조각들이 서로 안 겹친다는 보장은 아니다. 위쪽 가운데에 뜨는 스낵바는 폭이 넓어 오른쪽 위 체력바 위에 그대로 얹혔다 — 값이 가려져 남은 체력을 읽을 수 없었다. 

notice_anchor.avoid_peers = true      # 고정 HUD 아래로 내려앉는다
notice_anchor.reserve_space = false   # 떠 있는 동안 본문을 밀지도 않는다

비키는 것은 세로로만이다 — 좌우로도 밀면 가운데 정렬이던 알림이 뜰 때마다 다른 자리에 나타나 눈이 따라가지 못한다. 그리고 피하는 쪽은 비키지 않기로 한 칸뿐이다: 둘 다 서로를 피하면 두 칸이 영원히 자리를 맞바꾼다.

GoBar — 체력·마나·경험치

var hp := GoBar.new()
hp.label_text = "HP"
hp.ink = GoUi.color(GoTheme.DANGER_FILL)   # 채움 전용 토큰
hp.set_values(320, 500)                    # "320 / 500"

값 변화는 0.18초 보간한다 — 체력이 뚝뚝 끊겨 움직이면 얼마나 맞았는지 읽히지 않는다. reduce_motion 이면 즉시 바뀐다. 큰 수는 12.3k 로 줄여 막대 폭이 흔들리지 않게 한다.

GoSlot — 퀵슬롯 한 칸

아이콘·수량·쿨다운·단축키를 판 한 장에 담는다. 작은 원 위에 배지를 따로 달면 슬롯마다 실제 폭이 달라져 줄이 흔들린다.

보이는 크기와 터치 크기가 다르다. 슬롯을 촘촘히 놓으면 48dp 터치 상자가 이웃과 겹친다. 겹친 자리는 중심이 더 가까운 슬롯이 가져간다 — touch_peers 에 서로를 넣어 주면 된다.

keyboard_focus 는 기본으로 꺼져 있다 — 퀵슬롯 여덟 칸이 Tab 순회에서 키보드 사용자와 설정 컨트롤 사이를 막지 않게. 키보드·게임패드가 유일한 입력일 때 켠다.

GoJoystick — 가상 조이스틱

모드동작
FIXED늘 같은 자리. 위치를 기억하기 쉽다
FOLLOW처음 누른 자리에 나타난다. 큰 화면에서 손가락을 옮겨도 잡힌다
RELATIVE나타난 뒤 손가락을 계속 따라간다. 오래 끄는 이동에 편하다

moved 로 오는 Vector2 는 길이가 0~1 이라 그대로 속도에 곱하면 된다 — 화면 크기나 DPI 에 따라 값이 달라지지 않는다.

GoIconButton — 작게 보이고 크게 눌린다

헤더의 닫기 버튼이 제목보다 커 보이면 안 되지만, 36dp 사각형은 손가락으로 못 누른다. 그래서 노드는 작게, 히트 판정은 노드 밖까지 넓힌다.

형제가 입력을 받지 않을 때만 안전하다. 넓힌 영역이 옆 버튼을 덮으면 옆 버튼이 안 눌린다. 아이콘 버튼을 나란히 둘 때는 touch_peers 로 서로를 알려 준다.

기다리기, 알리기, 세기

GoSnackbar — 스스로 자리를 잡는 메시지

화면 아래(또는 위), 안전영역과 가상 키보드 위에 앉았다가 혼자 사라진다. 이것이 없으면 "저장했습니다" 한마디를 띄우는 화면마다 레이어·배치·타이머·정리 코드를 다시 쓴다.

snack.show_text("저장했습니다", GoTheme.SUCCESS)

# 되돌릴 기회 — 0 은 첫 버튼, -1 은 시간이 다 된 것
if await snack.post({"text": "아이템을 버렸습니다", "actions": ["되돌리기"]}) == 0:
    restore_item()

메시지는 서로 덮어쓰지 않고 줄을 선다. 같은 문장이 되풀이되면 하나로 합친다 — 1초에 네 번 실패하는 서버가 4분치 알림을 쌓아 올리는 일이 없다. 버튼 없는 스낵바는 입력을 그대로 통과시키므로 아래의 게임은 계속 돈다.

무언가를 묻는 자리가 아니다. 스스로 사라지니 플레이어는 끝내 못 볼 수도 있다. 되돌릴 수 없는 확인은 GoDialogs 의 몫이다. 여기 버튼은 눌러도 되고 안 눌러도 되는 것이어야 한다 — 되돌리기, 자세히, 다시 시도.

GoNotice 는 짝을 이루는 나머지 반쪽이다. 입력도 포커스도 절대 가져가지 않고, 어디에 둘지는 그것을 가진 화면이 정한다. 그쪽은 버튼을 달 수 없고, 이쪽은 달 수 있다.

GoSpinner — 끝이 보이지 않는 기다림

서버와 이야기하는 게임에는 이 페이지의 무엇보다 이것이 먼저 필요하다 — 가만히 서 있는 화면은 멈춘 게임으로 읽힌다. 한 줄이면 방금 누른 버튼이 그 자리에서 스피너가 된다.

GoSpinner.busy(buy_button, true)
var ok := await server.purchase(item)
GoSpinner.busy(buy_button, false)

버튼은 크기를 지킨다 — 글자가 없어지는 게 아니라 투명해지므로 줄이 튀지 않는다 — 그리고 도는 동안 눌리지 않는다. 뒤쪽이 핵심이다: await 하는 사이에 결제가 두 번 나가면 안 된다. reduce_motion 이면 돌지 않고 점 세 개가 깜박인다.

잴 수 있는 진행은 GoBar 다. 스피너는 언제 끝나는지 아무것도 약속하지 않는다.

GoBadge — 안 읽은 점, NEW 딱지, 99+

GoBadge.attach(mail_button, unread_count)   # 0 이면 스스로 숨는다
GoBadge.attach(shop_button, 0, "NEW")
GoBadge.attach(friend_button, 3, "", true) # 점 하나 — "뭔가 있다"

앵커로 대상의 오른쪽 위 모서리에 매달리므로 크기가 나중에 정해지는 대상도 따라간다. 두 번 붙이면 같은 배지를 돌려준다. 개수가 플레이어의 행동을 바꾸면 숫자를, "뭔가 있다" 만 중요하면 점을 쓴다.

글자 색은 스킨이 배지를 어떤 색으로 칠했든 그 색과의 대비로 고른다 — 흰색이라고 넘겨짚지 않는다 — 그리고 접근성 이름을 함께 단다. 색깔 점 하나는 화면 낭독기에 아무 말도 하지 않기 때문이다.

폼과 목록

GoField — 틀릴 수 있는 줄

입력 칸이 다섯인 폼 맨 위에 "입력을 확인하세요" 한 줄이 떠도, 그것은 어느 칸인지 말해 주지 않는다. 가입을 도중에 그만두게 만드는 것은 딱 그 하나다.

var name_field := GoField.make("캐릭터 이름", GoStyle.line_edit("2~12자"), "나중에 바꿀 수 없습니다")
name_field.set_error("이미 쓰고 있는 이름입니다")   # 서버가 거절했다
name_field.clear_error()

오류가 떠 있는 동안 도움말은 숨는다 — 줄이 한 줄만큼 자라 아래를 전부 밀어내지 않게. 그리고 오류 문구는 컨트롤의 접근성 이름에 함께 붙는다. 빨간 테두리만으로는 빨강을 못 보는 사람에게 아무 말도 되지 않는다.

GoStyle.field() 는 고정된 쪽이다 — 라벨·컨트롤·도움말, 오류 상태는 없다. 틀릴 일이 없으면 팩토리를, 서버가 거절할 수 있는 것에는 노드를 쓴다.

GoInputGroup — 버튼과 한 덩어리로 붙은 입력칸

GoInputGroup.make(GoStyle.line_edit("메시지"), {"suffix": GoStyle.icon_button(&"send", send)})
GoInputGroup.make(GoStyle.line_edit("이름"), {"prefix_icon": &"search"})

이것이 푸는 문제는 모서리다. 둥근 두 모양이 가운데서 만나면 잘록해 보이고, 기본 간격까지 있으면 따로 노는 두 물건으로 읽힌다. 바깥 모서리는 둥근 채로 두고 맞닿는 쪽만 각지게 한다 — 버튼의 모든 상태에서. 아니면 누르는 순간 덩어리가 갈라진다. 모서리를 깎아 낸 스킨에는 모서리 항목 자체가 없으므로 거기서는 손대지 않고, 각진 면끼리 깔끔하게 만난다.

GoCombobox — 검색되는 고르개

항목이 열 개 아래면 GoStyle.select() 가 낫다 — 누르는 횟수가 하나 줄고 목록이 한눈에 다 보인다. 서른을 넘으면 눈으로 훑는 것이 일이 된다.

var picker := GoCombobox.make(server_names, 0, "서버를 고르세요")
picker.picked.connect(func(i: int) -> void: connect_to(servers[i]))
검색은 이름의 첫머리가 아니라 이름 안을 본다. 앞글자만 맞춰서는 한국어·일본어 목록에서 거의 아무것도 찾지 못한다 — 두 항목을 갈라 주는 낱말이 맨 앞에 오는 일은 드물다.

GoCodeInput — 쿠폰·선물 코드

코드는 손으로 치기보다 메시지에서 붙여넣는 경우가 훨씬 많다. 진짜 입력칸을 열두 개 두면 붙여넣기가 첫 칸에서 끊기고 IME 에 글자를 잃는다. 그래서 글자는 숨은 입력칸 하나가 받고 칸은 그려서 보여 준다. ABCD-EFGH-IJKL 은 들어오는 길에 붙임표를 떼어 낸다.

var coupon := GoCodeInput.make(12, 4)
coupon.completed.connect(func(code: String) -> void: server.redeem(code))
coupon.set_error("이미 사용한 코드입니다")

GoTable — 정렬되는 머리줄, 눌리는 줄

var board := GoTable.make(
    [{"text": "순위", "width": 56}, {"text": "이름"}, {"text": "점수", "numeric": true}], rows)
board.row_selected.connect(func(i: int) -> void: open_profile(rows[i]))
numeric: true 를 빠뜨리면 순위가 뒤집힌다. 글자로 견주면 "9124" 가 "91240" 를 이긴다 — 점수도 골드도 피해량도 자릿수가 제각각이다.

row_selected 는 정렬된 자리가 아니라 원래 배열의 인덱스를 준다. 정렬 방향은 색만이 아니라 글리프로 보여 주고, 줄 전체가 눌리므로 칸 하나를 겨눌 필요가 없다. 읽기 전용 격자는 여전히 GoStyle.table() 이다.

GoPagination — 쪽 번호, 아니면 더 보기 줄

var pager := GoPagination.make(1, 12, func(page: int) -> void: load_mail(page))
var more := GoPagination.more(load_next)   # 모바일에 어울리는 쪽

번호는 마우스의 UI 다. 휴대폰에서는 더 보기 줄이 더 잘 읽힌다. 지금 쪽은 늘 창 가운데에 머무르므로 다음을 눌러도 번호가 통째로 뒤섞이지 않는다. 총 개수 0 은 "모른다" 는 뜻이고 화살표만 그린다 — 받지 않은 쪽 수를 지어내지 않는다.

게임이 실제로 쓰는 모양

웹에서 익숙한 모양들을, 게임이 그것에 바라는 것에 맞춰 다시 지었다.

GoRewardCalendar — 출석 보상

날짜 고르개가 게임에서 쓸모 있는 일은 거의 없다. 달력 모양은 다르다 — 출석 보상에서 중요한 것은 며칠인가가 아니라 몇 일째인가이기 때문이다.

var attendance := GoRewardCalendar.make(days, claimed_until)
attendance.claimed.connect(func(day: int) -> void: server.claim_day(day))

누를 수 있는 것은 오늘 칸뿐이다 — 눌러도 아무 일 없는 버튼은 고장으로 읽힌다. 받은 날·오늘·앞으로 올 날은 세 가지로 한꺼번에 갈라진다: 체크 글리프, 강조 테두리, 흐림.

GoRadar 와 GoDonut — 능력치를 한눈에

var stats := GoRadar.make({"힘": 0.85, "민첩": 0.5, "지능": 0.3, "체력": 0.7, "행운": 0.45})
stats.set_compare(with_new_sword)          # 점선으로 겹쳐 그린다

var share := GoDonut.make([{"label": "물리", "value": 620}, {"label": "마법", "value": 340}])
card.add_child(share.legend())

레이더 값이 0~1 인 것은 무엇을 가득으로 볼지가 게임의 결정이기 때문이다 — 힘 120 을 지능 45 옆에 날것 그대로 그리면 거짓말을 그리게 된다. 도넛 값은 날것 그대로 넣으면 나누는 일은 알아서 한다. 조각이 다섯을 넘으면 나머지를 하나로 접는다 — 여섯 번째 조각은 아무도 읽을 수 없는 실오라기다. 비교선은 색만 다른 것이 아니라 점선이고, 범례는 비율을 글자로도 적는다.

GoCarousel — 배너와 캐릭터 선택

banners.set_pages([promo, event, pack])
banners.autoplay_seconds = 5.0             # 기본은 꺼져 있다

시키지 않으면 스스로 넘어가지 않고, 5초가 하한이다 — 3초마다 바뀌는 배너는 글을 다 읽기도 전에 글을 걷어 간다. 손을 대면 타이머가 처음부터 다시 가고, reduce_motion 이면 스스로는 절대 넘어가지 않는다. 점은 작게 그려져도 터치 최소 크기로 눌린다.

GoKbd — 거짓말하지 않는 키 안내

hint.add_child(GoKbd.for_action(&"interact"))   # 실제 배정된 키를 읽는다

코드에 박아 넣은 "F 를 누르세요" 는 플레이어가 키를 바꾼 뒤에도 계속 F 라고 말한다 — PC UI 에서 가장 흔한 거짓말이다. for_action() 은 InputMap 을 읽는다. 그 동작이 패드에만 배정되어 있으면 빈 값을 돌려주고 위젯은 숨는다. "없음" 이라고 적는 것 역시 또 하나의 거짓말이기 때문이다. Android 와 iOS 에서는 스스로 숨는다.

화면 위에

GoDrawer — 옆에서 나오는 판

GoSheet 는 아래에서 올라온다. 세워 쥔 휴대폰에는 그게 맞다. 태블릿이나 데스크톱에서는 같은 시트가 게임을 덮어 버린다 — 그 자리에는 옆에서 나오는 판을 쓴다.

bag.side = GoDrawer.Side.RIGHT
bag.open("가방")

판은 화면 끝까지 가지만 내용은 안전영역 안에 머문다. 아니면 둥근 모서리가 첫 줄을 잘라 먹는다. LEFT 는 아랍어에서도 화면의 왼쪽이다. "글이 시작하는 쪽" 이 요점이라면 follow_text_direction 을 켠다 — RTL 에서 좌우가 뒤집힌다.

GoPopover — 붙어서 뜨는 카드

GoPopover.open(slot, item_card(item))

GoSurface 의 붙는 배치에 레이어·표면·기준 컨트롤·정리까지 미리 이어 둔 것이다 — 게임마다 몇 번이고 다시 쓰는 그 열 줄. 한 번에 하나만 열린다. 카드가 겹겹이 쌓이면 화면이 묻히고 어느 카드가 어느 칸의 것인지 아무도 알 수 없다. 스크림은 투명하다 — 장비를 견주려고 연 카드가 그 장비를 어둡게 만들면 안 된다.

마우스를 올리면 뜨는 툴팁이 아니다. 터치에는 올려 두는 동작이 없다. 마우스로만 드러나는 것은 플레이어의 절반에게는 없는 것과 같다.

GoContextMenu — 길게 누르기와 오른쪽 클릭

GoContextMenu.attach(item_slot, [
    {"text": "사용", "action": use},
    {"separator": true},
    {"text": "버리기", "action": drop, "danger": true},
])

PopupMenu 는 엔진에 이미 있다. 없는 것은 제스처다 — 0.5초를 눌러야 열리고, 손가락이 움직이는 순간 취소된다. 그래서 목록을 넘기다가 메뉴가 튀어나오는 일이 없다. 무엇을 눌렀느냐에 따라 항목이 달라지면 배열 대신 Callable 을 넘긴다.

길게 누르기에는 두 번째 길이 있어야 한다. 숨은 제스처를 스스로 찾아내는 사람은 없다 — 눈에 보이는 ⋯ 버튼(open_at())이나 아이콘, 아니면 첫 실행 안내 투어를 함께 둔다.

GoConsole — 개발자 콘솔

console.register("give", "아이템 지급: give <id> <개수>", give)
console.toggle()

치트와 디버그 명령을 둔다. 치는 대로 걸러 주는 목록이 있어 아무도 명령을 외울 필요가 없고, 화살표 키에 기록이 남는다. 무엇보다 위에 있으므로 확인창 위에서도 디버그할 수 있다.

릴리스 빌드에서는 열리기를 거부한다. debug_only 는 기본으로 켜져 있다. 치트 명령이 플레이어 손에 들어가면 게임의 경제는 첫날에 끝난다.

GoStyle — 만드는 자리를 하나로

Button.new() 를 직접 쓰면 화면마다 여백·높이·줄바꿈이 조금씩 달라진다. 그 차이는 코드 리뷰로 잡히지 않고 스크린샷으로만 보인다.

요약이 있는 목록 줄

GoStyle.list_button(GoIconSet.SWORD, "Oathkeeper", _inspect, Color.TRANSPARENT,
    "Longsword  /  Attack 42", false)

두 줄 항목은 위아래 여백이 같고 한 줄 항목보다 넉넉하며, 제목·요약 묶음이 아이콘 옆 세로 가운데에 선다 — 컨테이너가 줄을 더 높게 늘려도, 요약이 여러 줄로 접혀도 그렇다. 줄 전체가 그대로 한 번에 눌린다.

흐르는 줄의 함정

wrap_row 에 넣는 것은 자연 폭이어야 한다. 줄바꿈을 켠 채 두면 최소 폭이 거의 0 이 되고, 흐르는 줄은 그 최소 폭으로 칸을 잡는다 — 버튼 하나가 한 글자 폭으로 쪼그라들어 글자가 세로로 한 자씩 내려간다. 팩토리가 이것을 자동으로 막는다.

빈 목록을 빈 채로 두지 않는다

page.add_child(GoStyle.empty_state(GoIconSet.BOX, "아직 아무것도 없습니다"))

사용자는 빈 화면을 고장으로 읽는다.
