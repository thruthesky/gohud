생김새 바꾸기

gohud 의 겉모습은 세 층으로 되어 있다. 색만 바꿀 수도, 모양까지 통째로 갈아 끼울 수도 있다.

세 층

프리셋 하나가 이 셋을 묶는다. 비워 둔 칸은 기본값으로 떨어진다.

층무엇을 정하나바꾸는 법
Theme 색·치수·글자 크기, 그리고 엔진이 그려 주는 것의 모양 — 버튼 판, 입력 칸, 탭, 토글 그림 .tres 를 만들거나 tools/make_theme.py 로 생성
GoSkin 코드가 직접 그리는 것의 모양 — 조이스틱, 퀵슬롯 판, 코치마크 링, 칩, 스켈레톤, 구분선 상속해서 바꾸고 싶은 메서드만 덮어쓴다
GoIconSet 아이콘 84종. 텍스처 세트든 아이콘 폰트든 같은 이름으로 부른다 세트를 꽂거나 몇 개만 덮어쓴다
왜 Theme 하나로 안 되는가. StyleBoxFlat 의 모서리는 둥근 것뿐이다. 반경을 0 으로 두면 직각이고 그 사이는 없다. 사선으로 잘린 모서리도, 한쪽만 굵은 변도, 바깥으로 번지는 발광도 엔진이 그려 주지 않는다. 게다가 조이스틱과 코치마크는 _draw() 로 직접 그리므로 테마가 아예 닿지 못한다.

고르기

GoUi.use_preset(GoThemePresets.SCIFI_DARK)

이 한 줄이 테마·스킨·아이콘을 함께 바꾼다. 에디터에서 고르려면 프로젝트 설정 → Gohud → Theme → Preset, 설정 리소스에서는 GoConfig.preset 이다.

한 칸만 내 것으로

GoUi.use_preset(GoThemePresets.SCIFI_DARK)
GoUi.config.icons = my_icons     # 아이콘만 내 세트로, 나머지는 프리셋 그대로

theme·skin·icons 를 직접 채우면 그쪽이 프리셋보다 우선한다.

토큰

모든 색과 치수는 Theme 의 GoHud 타입 아래에 이름으로 산다. 숫자를 코드에 쓰지 않는 것이 규칙이다 — 이름으로 부르면 테마를 갈아 끼울 때 전부 따라 움직인다. 

GoUi.color(GoTheme.ACCENT)             # 색
GoUi.metric(GoTheme.GAP)               # 치수(dp)
GoUi.font_size(GoTheme.ROLE_CAPTION)   # 역할별 글자 크기
GoUi.box(GoTheme.BOX_CARD)             # StyleBox 사본

글자 역할

micro · compact · caption · body · button · subtitle · title — 역할은 크기의 이름이지 용도의 이름이 아니다. "제목" 이 아니라 "가장 큰 글자" 다. 그래야 화면마다 다른 뜻으로 쓰여도 크기 체계가 흔들리지 않는다.

둘 다 여느 StyleBox 처럼 Theme 리소스 안에 저장된다 — 즉 테마가 모양을 바꿀 수 있다.

여백은 content_margin_* 으로 준다. GDScript 로 StyleBox 를 상속하면 _get_style_margin() 이 불리지 않는다(Godot 4.7 실측). 내장 칸을 채워야 내용이 테두리에 붙지 않는다.

내 프리셋 만들기 — 파일 하나

테마 하나를 더하려면 원래 네 군데를 손으로 만져야 했다 — 생성기의 팔레트, 형태, 스킨, 프리셋 리소스. 이제 명령 한 줄이 그 자리를 다 놓아 준다. 

python3 addons/gohud/tools/new_theme.py neon --from scifi_dark --title "Neon"
python3 addons/gohud/tools/make_theme.py neon      # 테마 .tres + 컨트롤 그림
godot --headless --path . --import                  # 새 그림을 한 번 임포트
GoUi.use_preset(&"neon")                             # 끝 — 고르개에도 저절로 뜬다

첫 줄이 themes/palettes/neon.json 과 themes/presets/neon.tres 를 만든다. JSON 에는 from 으로 물려받은 테마의 값이 전부 풀어 적혀 있어, 무엇을 바꿀 수 있는지가 그대로 목록이 된다. 지우면 부모 값이 쓰이고, 적으면 덮어쓴다. 프리셋은 themes/presets/ 폴더를 스캔하므로 레지스트리 코드를 고칠 일이 없다 — 프로젝트 설정의 드롭다운에도 바로 뜬다.

스킨을 상속한다(선택)

테마와 형태로 닿지 않는 자리 — 조이스틱의 육각, 슬롯 배지, 코치마크의 조준 표식 — 만 스킨이다. GoSkin 을 상속해 바꿀 메서드만 덮어쓰고, JSON 의 skin 에 그 리소스를 가리키면 된다. 색만 바꾸는 테마는 이 단계가 없다.

약속을 검사가 지킨다. tools/check_scaffold.sh 가 매번 임시 테마를 만들어 — 강조색을 바꾸고 반경을 4 로 — 생성·토큰 반영·가독성 검사 통과까지 확인하고 되돌린다. 처음 돌렸을 때 강조색 하나 바꾼 테마가 8쌍 미달이었다: 생성기가 글자색은 밀면서 강조색은 그대로 쓰고 있었다. 그래서 강조색과 그 위 글자도 이제 생성기가 민다.

가독성은 재서 지킨다

"예쁘다" 는 취향이지만 "읽힌다" 는 측정할 수 있다. 흐린 회색 글자는 좋은 모니터에서는 멀쩡해 보이고 햇빛 아래 폰에서는 사라진다 — 눈으로 고르면 반드시 그렇게 된다. 

python3 addons/gohud/tools/check_contrast.py

테마 파일의 색 짝과 버튼 상태별 판 위의 글자를 WCAG 기준으로 잰다. 반투명한 색은 깔린 배경 위에 합성한 뒤 잰다 — 그대로 재면 화면에 보이는 것보다 좋게 나온다.

대상필요한 대비
본문 글자4.5 : 1
큰 글자(24px 이상)3 : 1
강조 테두리·아이콘3 : 1
장식 테두리2 : 1 — WCAG 는 장식에 3:1 을 요구하지 않는다

같은 색 틴트 위의 같은 색 글자

이 함정은 이 코드베이스에서 세 번 나타났다 — 눌린 버튼(강조색 판 + 강조색 글자), 위험 버튼, 그리고 칩. 색 견본으로 보면 예쁜데, 같은 색조라 명도 차가 없어 측정하면 곧바로 무너진다.

그래서 글자색을 손으로 고르지 않는다. 테마 생성기와 GoSkin 이 각각 배경 위에서 기준을 넘을 때까지 명도만 민다 — 색조와 채도는 지키므로 팔레트의 성격이 남고, 팔레트를 바꿔도 대비가 따라온다.

글자로 읽히는 색과 면으로 칠하는 색은 요구가 반대다

밝은 테마에서 경고색은 글자로 읽히려고 어두워진다(#96500A). 그런데 막대 채움이 그 색을 물려받으면 경험치 막대가 갈색이 된다. 색만으로는 풀 수 없다 — 노랑은 휘도가 본래 높아 어떤 회색 바탕 위에서도 3:1 이 나오지 않고, 트랙을 어둡게 하면 오히려 더 나빠진다 (1.52 → 1.06).

그래서 둘로 가른다. 색은 선명하게 — 팔레트에 warning_vivid 처럼 채움 전용 원색을 둔다. 경계는 윤곽이 — 바탕에서 3:1 이 안 나오는 채움에는 GoSkin 이 1dp 윤곽을 둘러 "어디까지 찼는지" 를 만든다. 

MY_LIGHT = dict(
    warning=hexc("9A5407"),         # 글자로 읽히는 색
    warning_vivid=hexc("F2A007"),   # 막대에 칠하는 색
)
빠뜨리면 알려 준다. *_vivid 없이 채움이 어두워지면 생성기가 막대가 칙칙하다 — 팔레트에 warning_vivid 를 더한다 라고 한 줄 남긴다. 말없이 나빠지는 자리를 말하게 만든 것이다.

떠 있는 판은 뒤에 무엇이 올지 모른다

HUD 는 게임 화면 위에 얹힌다 — 눈밭일 수도, 동굴일 수도 있다. 판이 반투명이면 뒤가 비쳐 판 색 자체가 달라지고, 그 위 글자의 대비도 따라 무너진다. 어두운 테마의 HUD 판이 82% 불투명일 때, 뒤가 밝으면 흐린 글자가 3.74:1 까지 묽어졌다 — 기준 아래다.

그래서 반투명한 판은 순백과 순흑을 깔아 보고 잰다. 게임 화면의 최악이 그 둘이기 때문이다. 기본 테마들의 HUD 판은 이 검사를 통과하는 선(92%)까지 불투명하다 — 유리 느낌은 남기면서.

같은 이유로 아이콘 색도 고정하지 않는다. 퀵슬롯의 그림이 흰색으로 박혀 있어 밝은 테마에서 1.11:1 로 판에 묻힌 적이 있다 — 글자와 똑같이, 자기가 놓인 판 위에서 읽히는 색을 따른다.

Python 검사와 Godot 검사가 범위를 나눈다. check_contrast.py 는 테마 .tres 를 읽고, 스킨이 실행 중에 섞는 색(칩·슬롯)은 검사 스위트의 skin contrast 섹션이 Godot 안에서 잰다.
